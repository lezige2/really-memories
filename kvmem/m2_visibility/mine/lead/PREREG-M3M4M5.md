# PREREG · M3 / M4 / M5 推进计划（14B 线）

2026-10-25 ｜ 依据 `docs/legacy-2026-10-24/STATUS-REPORT.md` §4.3–4.6 与 §9.1 #6/#7。**验收标准照抄原文，不另立。**

## 0 为什么要先做 M5 的核心（与 MD 的推进顺序不同，理由在此）
MD §4.6 排的是 M3 → M4 → M5，理由是「没有 M2/M4，M5 没有意义」。但今晚的负对照已经给了 M5 一个**现成失败案例**：
问「我的车牌号是多少？」→ 14B 答「苏A12345」，而装置里唯一真值是「浙B-3F19K」（不在挂载块内）。
M5 的验收就是「控制题不再编造」——**这个案例已经在手，不需要等 M4**。
所以顺序调整为：**M5 校验器核心（用现有四跑验证）→ M3 → M4**。M5 的「产品级」部分仍需 M4，但校验器这一步是独立的。

## 2 M5 —— 接地与弃答（先做核心）
**MD §4.5 原文**：「答案里的实体/数字是否出现在被挂载块的正文里？……不在 → 标红/重写为『未记录』。**验收：控制题不再编造。**」

交付：
1. `memory.db`（SQLite）：权威正文表，从 14B 三块的真实源文本 + 控制文本种子化，带 sha256 与块几何。
2. `m5_ground.py`：输入（答案全文，本会话挂载的 block_id 列表）→ 输出三值 `supported` / `unsupported` / `undecidable`，unsupported 给出被重写后的文本。
3. 四例回归（全部来自今晚已有 run json，不新跑 GPU）：
   | 例 | 输入答案 | 期望 |
   |---|---|---|
   | 住址 | 我住在广陵路 12 号 2 单元 602。 | supported |
   | 项目 | 项目将在 3 月 14 日上线。 | supported |
   | 习惯 | 我喝咖啡的习惯是只喝美式，不加糖。 | supported |
   | 车牌 | 我的车牌号是苏A12345。 | **unsupported → 重写为未记录** |

**判据先由检测员冻结，冻结后才允许实现。** 关键风险是假阳性（把正确回答判成不支持）。

## 3 M3 —— 块生命周期管理器
**MD §4.3 原文**：
- pin/refcount：「块被对话引用时不能 reset 源 seq」
- 保存时机：「**文件只读**，永不回写；需要回到 0 位就从文件重新加载」（附：L3b 已证伪「再旋转一次即可」）
- 碎片：「位置连续 ≠ cell 连续……要监控 cell 池余量」
- **验收：attach/detach 50 轮，`pos_max`、answer、cell 占用三者稳定，无单调上升。**

交付：引用计数表（pin/unpin）+ 只读策略的代码级强制 + 50 轮 attach/detach 实测 json（含每轮 pos_max / cell 占用 / 答案）。
另有 §9.1 #6 附带任务：定量 `seq_cp` 不追加 token 的实际后果（在什么条件下撞车）。

## 4 M4 —— 写入固化
**MD §4.4 原文**：分段（~500–1000 token）→ 判据（值得记的事实/承诺/偏好；忽略寒暄）→ `write_at(seq, text, 0)` → `save` → 插 SQLite，**编码时必须独占 position 0**（L6）。
**验收原文**：「一次对话后自动沉淀 1 块，**新进程**能检索并正确回答。」

前置：M3 完成 + M1 索引接入（`facet_budget.py` 目前仍是实验脚本）。
交付顺序：分段器 → 判据 → 写入管线（含 position 0 独占断言）→ 新进程检索验证。

## 6 判定纪律（沿用整晚）
- 四词：未检验 / 实验无效 / 未测出·欠功率 / 无效应；「实验无效 ≠ 假设被否证」
- 判据先在数据之前冻结；判据要比事实宽，不能比事实严
- 子代理的报告是证据不是判决；队长独立复核 ≥1 项硬证据
