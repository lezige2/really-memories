## 3.15 一个会让实现走岔的歧义：摘录是 7 条还是 4 条
检测员给的计数 `(user 7, assistant 2, 被覆盖 4, 未覆盖人类行 3)` 有两种读法：
**A** 层 1 摘录 = 全部 7 条人类回合；**B** 只建被层 2 事实覆盖的 4 条。**裁 A。**
**理由：覆盖与可检索是两件事，不能混。**
- **层 1 摘录（源侧）** = 7 条人类回合 => 决定「一句话能不能**支撑**答案」；
- **层 2 事实 + 检索索引** = 4 条 => 决定「一个问题能不能被**命中**」。
所以 L1「你好呀！」/ L7「帮我查下明天天气。」/ L8「谢谢，就这样吧。」命中不了，**不是因为它们不是源，而是因为没被抽成事实、进不了检索**。
混在一起的后果：以后会出现「明明是人类说的却是 undecidable」和「把 undecidable 当源缺失来修」两种错误。
**因此报告弃用四元组、改五元组**，把两件事分开列：
`(user 行数=7, assistant 行数=2, 层1 摘录行数=7, 被层2事实覆盖的行数=4, 可检索事实数=4)`，并写明「L1/L7/L8 是**不可检索**，不是**不可支撑**」。

**R15-d 两条（检测员提，我收编）**：
1. **摘录元组是五元组** `(container_name, container_sha16, line_index, line_text, role)` + 硬断言 `line_text == container_text.split(换行)[line_index-1]` **逐字节相等**。
   理由：**纯行号索引脱离版本就是定时炸弹** —— 容器改一行，`[3,4,5]` 会静默指到别的句子而一切看着正常。
2. **角色只作准入闸门，不得用于任何内容判断**，否则会长出「人类行里的日期算、助手行里的日期不算」这类没法解释也没法验收的规则。

**一条本节最有价值的观察（检测员给的）**：既有 4 条 fact 溯源是 住址_2→L3、作息_3→L4、车牌_4→L5、家庭成员_5→L9，
**全是用户行、全是逐字子串** => D4 过滤此前行为是对的；**但这也意味着枚举标错今天是隐性的**（把 L2 标成 user 也不改变任何结果，因为 L2 没有事实）。
=> 显式枚举 + sha16 绑定 + 逐字节断言防的是**将来**：某条助手发言恰好含一个硬事实时被静默存进层 1，**那一刻没有任何字节层面的东西会报错**。

**R15-e 容器版本变更**：容器 text 任何字节变化 => 枚举整体失效、重新声明并重建、旧摘录标 stale（不许沿用行号）。
**R15-f 跨层可见性**：分层判重后必须保留 `derived_from` 非空 + 逐字子串断言，否则退化成「看不见的重复」。
**我另加**：角色声明可被推翻 —— 改 role => 该容器摘录集整体失效重建（与容器变更同等），不许就地改字段。

容器版本锚：`conv_2026-10-25 @ d8c094c1f5fcb8f1`（127 字符 / 9 行）。

## 3.18 I8 / I8-b：装饰列比错误默认值更严重
**代码事实（我核过原文）**：`assert_m5_source_allowed` 里 `turns` 只被拼进报错文案与返回值，**没有任何一处用它做决定**：

```
    raise SourceNotAllowed(... "contains_model_turns=%r" ...)   # 仅文案

```
=> 一行 `text_kind=human_memory` + `contains_model_turns=1` **会通过闸门**。这一列是**装饰性的**：写入、展示、却从不校验。
**我提的 (A)(B) 两个选项都被否，且否得对**：
- **(A) 从 text_kind 派生错**：`conversation ⇒ turns=1` **不成立** —— 一份纯人类发言的会话记录，`conversation`+`0` 是合法事实；强行派生会把它错标。

- **(B) 双向 CHECK 错**：会禁止一行合法数据。

**采纳 (C)**：
1. 两个默认值**各自** fail-closed：`text_kind DEFAULT 'conversation'`、`contains_model_turns DEFAULT 1`（今天 `human_memory`/`0` 是**双重放行**）；

3. **闸门并列判三项**：`human_memory` 且 `turns=0` 且（`is_excerpt=1` 时）`derived_from` 非空 + 逐字子串。

**可判证据三条**：(i) 只用老列 INSERT => 读回 `conversation`/`1`；(ii) 人造 `human_memory`+`1` => 被拒；
**(iii) 绕过 CHECK 直接改副本库造出 `human_memory`+`1` => 闸门必须抛 `SourceNotAllowed`** —— 这条专证「闸门读了这个列」，比任何默认值都更能说明它不是装饰。

## 3.31 第六条纪律的修正：分界不是「细 vs 粗」，是「有没有事先声明期望」
原写法「整体性陈述不合格」不够准。检测员推进了一格，我采纳为准：
> **逐列 + 事先声明的期望 + 机器比对，三者缺一都不构成材料。**
> 逐列但不带期望 = **把判断责任推回给读者**；带期望但不机器比对 = 靠人记得去比；机器比对但没事前声明期望 = **用事后补的期望去迁就结果**。
**实例（检测员自述）**：它逐列报了 `_m5db` 四个变化，"看着很细"，**但没把列分成「该变/不该变」两类**，所以"细"并没有换来"能判断"。

**并补一个必要前提**：`changed_columns` 的等式要求**比对同一批行**。故必须同时给三个集合：
```
changed_columns == {"source_text", "text_origin"}
added_blocks   == {}
removed_blocks == {}
```
否则行集变了而列集合恰好不变 => **「逐列过、逐行不过」**。换源不该增删块。
**顺序**：行集先于列集 —— 列集在一个形状已变的表上比毫无意义。

这样"这针从哪抄的"不靠记忆，靠注释；来源错了，改起来是改一行注释而不是重查一圈。
**纪律九之二（我加）**：**凡断言「X 不出现」，必须另有一条断言证明「同一个 X 在别处出现」。**
否则打错一个字符，断言就永久为真 —— **而「永远为真」和「通过」在报告里长得一模一样**。
**通 2 说「要能失败」，纪律九之二说「证明它真的能失败」。**

**我的错误的两个方向**：同一个错串 `m2_link`（实为 `m4_layer2_link.py --apply`）
- 在**阳性**断言里 => 表现为 FAIL（检测员那次，它查出来了）；
- 在**阴性**断言里 => 表现为 PASS（执行者那次，看起来像通过）。**后者更危险。**

## 3.56 纪律十：期望不得取自被检验产物本身（循环期望）
**实证**：`PREREG-STAGE3-11ROWS.json`（`28d63cb8589ae10c`，11 行）里，
| 行 | `expected_basis` | 判定 |
|---|---|---|
| 7 条探针 | `m4_verify_grounded.py PROBES expected_after literal`（脚本 `9247e3fa`，04:03 早于 Stage 3）| **合法**：代码字面量，逐条比对**零不符** |
| 4 条产品 | `run_m5_grounded.json cases[plate_main].verdict` | **循环**：期望取自**它要预测的那份 run** |
**⇒ 那 4 行的 `matches_expected: true` 是空的（同义反复）。**
**`authored_at > run` 救不了它** —— 时间戳只证明"写得晚"，内容仍来自结果。**这是"倒签的变体"，比"散文出处无法 git 定位"更直接：它指回了结果本身。**

**正确写法**：4 条产品行**本来就该以「不变」为期望** ——
依据 = 冻结判据「裁决不变」（写在实现之前）；**值取重建的 before 侧**（检测员 R 级），**不得取 run 的 `cases[*].verdict`**。
改完之后 `matches_expected` 才有内容：**它检验的是"观测值 == 重建的 before 值"。**
**数值不改**（检测员核过是对的：plate_main supported / home_main supported R 级；两条 ablated C 级）—— **这不是数据错，是依据错。**

**这正是纪律六预言过的第三种失败**：**机器比对但没事前声明期望 = 用事后补的期望去迁就结果**。
它当时的话我原文收：**没有独立落盘的期望，交回时只能拿它的运行结果当期望，「逐行相等」就必然成立、也一无所得。**

## 3.57 住户与过客：`raise` 的文案是过客，origin/note 是住户
**纪律八的适用对象是「人读到的、含动作的文案」，不限 `raise` 的消息体。**

## 4 本轮踩到并验证过的五个陷阱（写进交接，别再踩）
1. **`reset_all(eng)` 会清块槽** —— 它是 `for s in range(N_SEQ): eng.reset(s)`。在已挂载状态下调用会静默丢掉记忆。
   M3 第一跑因此产出 74 分钟无效数据，归档为 `run_m3_50_INVALID.json`（保留不删）。正确写法：只 reset 对话 seq，或用 `safe_reset_all`。
2. **shim 的 `pos_max` 报 -1，而 raw 是 4095** —— 任何拿 shim `pos_max` 做判断的上层都是错的；M4/M5 要用必须用 raw。
3. **`reset(块seq)` 不报错、静默清空**（21 cell → 0、pos_max → -1），块文件不变。安全依赖「先 detach 再 reset + 从文件重载」。
4. **块不在锚点前就提问 = 静默空答**：`ask` 只在 `pos == raw_pos_max+1` 生效。块编码在 position 0 时必须先重排到「结束于锚点」，
   否则 `rc=-1`、返回空串、不报错（本轮 [0,91) vs [4005,4096) 已对照实测）。
5. **`safe_reset_all` 不能用在放置路径** -- 它 `skip = set(skip) | set(self.blocks)`，**无条件跳过所有已注册块 seq**；在 `chat.py:176/:284` 这类「清块槽再 load_into」的地方调用它，块根本不会被清，`load_into` 会**叠在旧 cell 上**：位置悄悄错、cell 悄悄多、还不报错（陷阱 1 的镜像）。放置路径必须用 `leases.reset(seq)`，并断言 `cells_of(seq)==0`。
