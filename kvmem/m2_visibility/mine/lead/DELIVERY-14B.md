## 2 为什么不能写「成立」（三条，按硬度排）
1. **判据在 14B 上饱和**：fact_ok(广陵路) 在 run0/E/F/X1/B57/P2 六个配置上**全为真** => 它不能区分四格 => 「四格全过」不携带信息。
2. **24 token 的「齐一」是截断假象（实测，非推断）**：五个格位的 24 token 答案都是 64 token 答案的**字面前缀**（队长复验全 True）；
   字面分岔点：E<->B57 char 27、E<->F char 33、F<->X1 char 45（执行者按 14B 分词器折成 token 24 / 28 / 37，全部 >= 24）。
   这正是 24 批看不出任何差别的原因。
3. **64 token 下 F 出现污染**：np64_F 两跑逐字节相同，答「我住的小区叫**蓝鲸**」「我住的小区是**三月十四**」，把 pp18 的内容当自家事实复述；
   np64_E 同位置答「我住的小区叫广陵路 12 号」。事实句仍在（故 fact_ok=True），污染整体落在判据盲区。

## 3 可以写的四句（交付边界）
1. **跨模型只此一句**：同一 fact_ok 判据下，7B 的 F = 败、14B 的 F = 过（序数对比，不做任何数值比较）。
   注意这条只弱支持「失败阈值上移」，**不足以**判规模假设成立；也**不可**反推「14B 扛住改写」。
2. **14B 内部**：slot4 的内容**确实被读**（P2 只换 slot4，输出第 1 字符即分岔，两跑稳定）；但 14B 在 69 格下**事实层 10 跑全读对**。两句必须成对出现。
3. **编码保真**：同一问句、同 18 格单块几何、只换块 —— project 答「3 月 14 日」、pp18 答「三月十四号」，**措辞跟着块走** => .kvmem 携带各自具体内容，非平均/模糊表示。
4. **负载方向一致（未定稿）**：同为 slot4=pp18，F（69 格）污染、B57（57 格）未见污染；F 与 B57 的唯一几何差别就是 habit 块在不在。
   但仅 2 跑、定性判读、非预登记量 => 只记辅助观测，**不升级为判定量**。

## 5 撤回（五条，含队长自己的三条）
1. HANDOFF §8.7「c7ea09bb 全盘无副本 => E/F 不可复跑」为**假**：该 DLL 存在，已归档，49877504 字节，sha 相符。
2. 旧 fixtures.json 的 dll_sha256=c7ea09bb 是**陈旧常量**，不能当 provenance。
3. 3a726dbd **已永久丢失**（未归档即被覆盖）；两方独立扫描（队长全盘枚举、检测员仓库内逐字节）均未发现，扫描粒度差异已并列记录。
4. **队长错判一**：要求「libllama.a 的 mtime 必须变」作为编译判据 —— 该判据只能靠源码漂移满足，本身是错的。
5. **队长错判二**：「造 14B 块必须改 probe:85」—— 前提不成立，运行时赋 P.MODEL 已足够；执行者拒绝执行是对的。
6. **队长错判三（最重）**：用「P2 证明仪器对 slot4 敏感」去论证「slot4 对结果无影响」，并把仪器分辨力当成判据分辨力，据此判「规模假设成立」。
   方向反了：越敏感，24 token 的「齐一」越可能是截断。由检测员在最后一刻顶住，数据（64 批）证实其判断。
