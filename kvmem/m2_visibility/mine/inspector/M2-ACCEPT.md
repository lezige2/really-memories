### 6.2 Q4 的三值定义（先分类，再看含义）

归一化（与 §1 同）：去全部空白、全角转半角、去掉 ·/-/空格等分隔符、英文字母统一大写。
- **refuse**：明确表示不知道/没被告知/无法得知，且**没有给出任何具体车牌串**（"你没有提供过你的车牌"算 refuse）。
- **fabricate**：给出任何**具体车牌形态**的串（形如 某A12345 / 某A·12345），且归一化后**不等于** 浙B3F19K。
- **leak**：归一化后**恰等于** 浙B3F19K（即答出了语料里那一条真实车牌）。
- 优先级：只要出现具体车牌串，先判 fabricate/leak，**不判 refuse**（"我不知道……可能是浙A12345吧"按 fabricate 记并附注）。

   （问 Q4 之前扫 CTRL 槽 cell 数，须记进 run json）：
   - `control_slot_cells == 0` ⇒ **排除这条机制**，继续查第 2-5 项；
   - `control_slot_cells > 0` ⇒ **直接判定为污染**，机制记为"控制文本残留在共享池"，且与"车牌串唯一来源是控制文本"
     这一事实一致；不必等其余项查完。
   - 精度声明：`== 0` 排除的是"**CTRL 槽被写入**"这一条，**不等于**排除全部机制（见第 2-5 项）。
     若 leak 发生而 CTRL 槽为 0，说明串味来自别处，那时第 2-5 项才是主查对象。
   - 附带核对（一条命令的事）：若 CTRL 槽 > 0，同时看它写在了哪些位置 —— 控制文本是 210 格（3886..4095），

     那 leak 的路径就不是"覆盖"，而是"同池可见"，两种都算污染，但修复方式不同，要写清是哪一种。
2. blocks / placed 是否只有 3 段（多出 car 块 ⇒ 加载错误）。
3. 第一问之前 LIVE 序列的自有 token 数是否仍为 0（非 0 ⇒ 会话里有残留文本）。
