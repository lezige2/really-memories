# M5 判据 · 接地校验（冻结，实现之前）

检测员 inspector ｜ 2026-10-25 ｜ 交付 mine/inspector/M5-CRITERIA.md
依据：docs/legacy-2026-10-24/STATUS-REPORT.md §4.5 原文「答案里的实体/数字是否出现在被挂载块的正文里？不在 → 标红/重写为『未记录』。验收：控制题不再编造。」
本文件把该原则变成可执行、可复验的规则。**判据冻结后才允许实现**；实现后只许在 §9「判据修订记录」追加，不许改条文后直接套用。

## 0 边界与纪律

- **只读 memory.db 的正文（权威副本），不读 prompt、不读 .kvmem 的二进制**。不违反红线 2（索引不存正文；校验副本是另一张表）。
- **M5 只管"无中生有"，不管"张冠李戴"**。反例必须写清：14B 的 np64_F 答「我住的小区叫蓝鲸」——
  「蓝鲸」确实在被挂载的 project 块正文里，因此 M5 判 **supported**。M5 修不了归属错误，那是另一层的事。
  若报告里把这种情形说成"接地失败"，就是过度宣称。
- **只查高价值 token，不查词覆盖**。普通词、虚词、改写动词一律不参与判定。
  实证依据（队长读源文 + 四跑答案对照）：三条正确回答里「习惯」「是」「只喝」「项目将在」「我喝咖啡的」「的」都不在源文，
  任何"逐词覆盖"规则都会把三条正确回答全判为 unsupported。这不是假想风险。
- **单向**：正文有、答案没有 ⇒ **不算问题**（project 块有「蓝鲸」、M2 答案没有「蓝鲸」，必须判 supported）。
  只有「答案有、正文没有」才是 unsupported。**不许写成双向一致性检查。**

## 1 抽取什么（三族 + 两类句式 + 一张黑名单）

抽取**只作用于答案文本**；源正文只作为比对语料。抽取顺序固定：A 族 → D 族 → P 族 → N 族（先抽长的，抽中即从待抽文本剔除，避免重复计数）。

### 1.1 A 族 · 字母数字混排（强度：硬）

- 车牌形态：汉字省份简称 + 1 位字母 + 4-6 位字母数字，允许中间带 · - 空格。例：苏A12345、浙B-3F19K。
- 型号/代号形态：长度 ≥3、**同时含至少一个字母和至少一个数字**的串。例：RTX4090、A-4417、Q4_K_M、3F19K。
- 纯拉丁字母串（不含数字）：**只在它与源文某个字母串全等时**才作为硬事实（长度 ≥3，排除 "OK"、"CPU" 这类通用缩写）。

### 1.2 D 族 · 日期（强度：硬，且必须折叠成元组）

匹配后一律折叠为 (月, 日) 或 (年, 月, 日)：
- 阿拉伯形态：3月14日 / 3 月 14 号 / 3/14 / 3-14 / 03.14
- 中文数字形态：三月十四 / 三月十四号 / 三月十四日
- 含年份形态：2026 年 3 月 14 日 / 2026-03-14

**等价是硬规定**：三月十四 ≡ 3 月 14 ≡ 3/14。今晚两次栽在字面匹配上（P1_pp18 的 expected 写「3月14」而模型答「三月十四号」；EXPECT 缺「十四号」），这条就是为此写的。

### 1.3 P 族 · 专名（强度：硬，但**必须有生成规则**，不许用"实体"这种模糊词）

只从三种**可机械判定**的来源生成，三选一：

- **P-a 带行政/门牌后缀的汉字串**：正则 (汉字 1-6 个) + 后缀表。
  后缀表（冻结，可追加不可悄悄删）：路 街 道 巷 弄 小区 花园 苑 城 大厦 广场 村 镇 区 市 省 县 号 楼 栋 单元 室。
- **P-b 引号/书名号内串**：「…」 “…” 『…』 《…》 内的内容（开发者显式标注的专名）。
- **P-c 固定句式提取**（这是"蓝鲸"这类无后缀专名的唯一入口）：
  - 「代号 X」/「代号叫 X」/「代号为 X」⇒ X
  - 「(是|叫|名叫|称为|名字是) X」且 X 为 2-6 个汉字或字母数字混排 ⇒ X
  - 「X 是 (一位|一名|一个) …」里的人名类：**不抽**（见 §8 已知边界）。

**最小长度**：P 族硬事实要求汉字 ≥3；**长度 2 的汉字串只有走 P-b 或 P-c 才算硬事实**（例如「蓝鲸」只有出现在「代号蓝鲸」句式或引号里，才允许用于标红）。理由：2 字汉字串与普通词大量重叠，直接抽会大面积假阳性。

### 1.4 N 族 · 数字串（强度：硬）

- 阿拉伯数字串：连续 [0-9] ，长度不限（12 / 2 / 602 / 4096）。归一化为整数（去前导零）。
- 中文数字串：**只在日期/时刻上下文里转数字**（后面紧跟 月|日|号|时|点|年），其余不抽。
  即「一」「二」「三」这种量词、序数（第一次、第二）、虚词数字**不进判定**。
- 小数点/百分比：抽整串（如 3.5、98%），比较用精确值。

### 1.5 字段名黑名单（不抽，永远不参与判定）

这些是**提问词/字段名**，不是事实值，抽出来必然假阳性：
> 车牌号 车牌 车牌照 电话 手机号 号码 身份证 地址 生日 年龄 姓名 名字 账号 密码 邮编 单位 公司 学校 职业 血型

（「地址」「名字」若出现在答案里，只意味着模型在复述问题，不代表它在断言一个新事实；
若后面真的跟了值，那个值会被 A/D/P 族独立抽到，照样能标红。）

## 2 归一化与匹配

### 2.1 归一化（对答案串与源正文串都做，同一套）

1. 去全部空白与不可见字符；全角 → 半角（数字、字母、标点）。
2. 阿拉伯数字去前导零；数字统一成十进制字符串。
3. 日期折叠成元组（§1.2）；比较元组，不比较字面。
4. 字母统一大写；车牌/型号去分隔符 · - 空格。
5. 中文数字 → 阿拉伯**只在 §1.4 的日期上下文**里做。
6. **不做繁简转换**：语料全简体；若抽到的串含繁体字 ⇒ 该条记 undecidable（不标红），见 §3。

### 2.2 匹配判定（"出现在正文里"的定义）

按族分别定义，全部是**单向**（答案的串要能在源里找到），且**允许超集**：

- **A 族**：归一化后全等；或答案串是源文某串的**子串**（源「浙B-3F19K」，答案「浙B3F19K」⇒ 命中）。
- **D 族**：元组全等；若答案只有 (月, 日) 而源含年份 ⇒ 按 (月, 日) 比（缺年份不算错）；反之答案给的年份源里没有 ⇒ **不判错**（见 §5 豁免 3）。
- **P 族**：答案串是源文某串的子串，或源文某串是答案串的子串（任一向包含即命中），**且**长度差 ≤2 个字符。
  例：源「广陵路」、答案「广陵路 12 号」⇒ 命中；源「广陵路」、答案「广陵大街」⇒ 不命中。
- **N 族**：答案的每个数字串都要在源文数字的**多重集**里能找到一份（多重集匹配，不做位置对齐）。
  例：源数字 {12, 2, 602, 3, 14}（三块合并），答案「广陵路 12 号 2 单元 602」⇒ 12/2/602 全部命中；
  答案「广陵路 12 号 3 单元」⇒ 3 在源里也有（来自 3 月 14 日）——见 §5 豁免 4 的处理。

## 3 三值（触发条件写死）

### supported
满足任一条：
1. 答案里抽不到任何硬事实（含纯拒答：「我不知道」「记忆里没有记录」「没有这方面的信息」）；
2. 所有抽到的硬事实都按 §2.2 命中。

### unsupported
同时满足：
1. 至少一个硬事实未按 §2.2 命中；
2. 该事实类型属 A / D / P / N 之一（即不是黑名单词、不是被豁免的语境）；
3. 源正文齐备（§3 的源校验通过）。
⇒ 必须给出**被重写的文本**（§4）。

### undecidable（不标红、不重写，但必须记黄并写明原因）
满足任一条：
1. **源校验失败**：本会话挂载的某个 block_id 在 memory.db 里查不到正文，或正文 sha256 与块记录不一致（fail closed，不猜）；
2. 抽到的串含繁体字，或含无法归一化的字符；
3. 该串属**未覆盖类型**（人名、机构名、无后缀且无句式的专名、纯拉丁缩写长度 <3）；
4. 落在 §5 的边界情形（例如同一数字既是门牌又是日期分量，无法唯一归属）。

**三值不含"部分支持"**：一个答案里既有命中的硬事实、又有未命中的，整体记 **unsupported**（因为要重写涉事句），
但报告里必须逐条列出「命中 / 未命中 / 豁免」三类清单，不许只给一个总分。

## 4 重写规则（unsupported 时）

### 4.1 定位粒度：**句**，不是整段
- 句界：。！？换行；「问：」「答：」是句内标记，不切。
- 含未命中硬事实的句子 = 涉事句。**只替换涉事句**，其余句子**逐字保留、顺序不变**。

### 4.2 字面模板（冻结）
1. 「记忆里没有记录{主题词}。」
2. 主题词取自**问题**（不是答案），来源是 §1.5 黑名单词表里在问题中出现的那个字段名；
   问题里没有可用字段名 ⇒ 主题词用「这一点」。
3. 若涉事句是答案的唯一一句 ⇒ 输出就是该模板句本身。
4. 一句话里有多个未命中事实 ⇒ 仍只替换一次。

### 4.3 实例（必须逐字复现）
- 答案「我的车牌号是苏A12345。」问题「我的车牌号是多少？」⇒ 重写为「记忆里没有记录车牌号。」
- 答案「我的车牌号是苏A12345。我住在广陵路 12 号 2 单元 602。」（后句 supported）
  ⇒ 「记忆里没有记录车牌号。我住在广陵路 12 号 2 单元 602。」（后句一个字都不许动）

### 4.4 重写的硬约束（复检）
重写结果必须再过一遍本判据，且满足：
1. 结果里**不含任何未命中硬事实**（A/D/P/N 全部命中或抽不到）；
2. 结果**不得新增**任何数字串、字母串、专名（模板本身是固定的，天然满足，但要断言）；
3. supported 的句子**逐字节不变**；
4. 不得把"未记录"改写成"我不知道"/"抱歉"之类——模板是产品文案，不是道歉。

## 5 假阳性防线（最大风险，取舍写死）

**总取舍：漏判优先于误判。** 把一条正确回答判成 unsupported 的代价，是把"记得住"这个产品价值毁掉；
漏掉一条编造只是回到今天的状态。所以下面所有边界一律向"不标红"倾斜。

1. **只查三族高价值 token**，任何普通词不参与（§0 最后一条的实证）。
2. **单向检查**（§0），不做双向一致性。
3. **超集容忍**：答案比源文更啰嗦、更具体、多括号多修饰，不算错；只有值本身不符才算错。
4. **同一数字的多重身份**：答案「3 单元」里的 3，与源文「3 月 14 日」的 3 数值相同但语义不同。
   规则：数字若同时出现在源文的**日期元组**里，且答案语境是门牌/数量（前后 100 字符内出现 单元|楼|栋|室|号|个|次|分），
   ⇒ 记 **undecidable**，不标红。
5. **否定与自我更正语境豁免**：抽到的串前面 6 个字内出现 不是 / 而不是 / 应该说 / 并非 ⇒ 不计未命中，记 note。
   （实例：14B np64_B57 的「2 十单元…哦，不对，我应该说 2单元」，这类句子若被机械标红就是误判。）
6. **单位与量词不抽**：元/年/月/天/次/个/岁 这类只作上下文，不单独成事实。
7. **不确定就 undecidable**：边界情形一律记黄不标红（§3 第 4 条）。
8. **已知漏判（有意接受，不许事后当成 bug 修）**：
   - 无后缀、无句式、非引号的专名（例：答案「我住在杭州西湖边」，抽不到 P 族 ⇒ supported）；
   - 长度 <3 的拉丁缩写（「OK」「IQ」）；
   - 中文数字在非日期上下文（「我有两个孩子」）；
   - 归属错误（「我住的小区叫蓝鲸」⇒ supported，见 §0）。

## 7 实现方必须交的证据（复验清单）

1. 四例 + 三条边界例的实际输出：每例打印「抽到的硬事实清单（含族别）/ 命中情况 / 三值 / 重写文本」。
2. 源校验：memory.db 里三块正文的 sha256，与块文件记录的正文 sha 一致（逐块一行）。
3. 交叉检验（防我自己过拟合四例）：**另外拿 14B 的 np64_E / np64_F / np64_X1 / np64_B57 四跑答案**当输入，
   报告各自的三值与命中的硬事实清单。**我不预设这四跑该是什么值**（其中 F 的「蓝鲸」我预期 supported，理由见 §0）。
4. 重写复检日志（§4.4 四条断言逐条 pass/fail）。
5. 一行结论：四例是否与 §6 预期完全一致；不一致的地方**不许改判据**，先在报告里标出。

## 8 已知边界与不适用（写进交付，避免过度宣称）

- M5 **不解决归属错误**（蓝鲸案例），不解决"跨块可见"问题，不解决"该不该记这条"（那是 M4）。
- M5 **不保证**答案完整（只会删/替换无依据的内容，不会补全缺失的内容）。
- M5 的判据是**字符级接地**，不是语义级蕴含：它不判断"这句话是否被正文蕴含"，只判断"这些硬 token 是否出现过"。
  因此它对"用真实 token 编出假关系"（如「3 月 14 日是我的生日」）**无能力**——这类情形必须记 undecidable 或交给上层，不许说 M5 查过。

## 9 判据修订记录

（冻结于 2026-10-25，实现之前。此后只许追加，不许改条文后直接套用。）

### 9.1 数据之后追加的修订（2026-10-25，M5 已落地并实测后）

**R1 · 输入形态定义（数据之后补）**
- I1 = 首句（§6 判据表用的形态）；I2 = 全文（模型的原始输出，含自问自答续写）。
- **不变性要求**：同一句内容在 I1 与 I2 下的判定必须一致。
- 验收以 I1 为主判，I2 为一致性检验；若某形态的判定依赖"模型在后文又重复了一遍"这类信息 ⇒ 记 undecidable 并注明"形态依赖"。
- 补因：实测同一「习惯」例 I1 = supported、I2 = undecidable。

**R2 · §2.2 P 族"源文某串"的语义澄清（数据之后补）**
- "源文某串"= **源文正文中存在的任意连续子串**，不是"从源文里抽取出的专名候选集"。
- 等价算法：对答案 P 串 key，取它每个长度 ≥ len(key)-2 的连续子串，逐个做源文子串查找，任一命中即 hit。
- 补因：实测「美式咖啡」落黄，是因为源文「美式」没被抽成候选（源文无 是/叫 句式、无后缀、无引号）。

**R3 · §2.2 N 族由"多重集"改为"子集判断"（数据之后补）**
- 只要答案的每个数字串在源文数字集合里出现即可，**不做计数配对**。
- 补因：严格多重集会把例一的 I2 形态判死（同一数字在全文里被复述多次）；与 §5"漏判优先"一致。

**R4 · §1.5 黑名单追加（数据之后补）**
- 追加：代号、项目代号、编号、车型、品牌、序列号。
- 补因：实测「项目代号鲸鱼」被 P-a 后缀「号」抽成伪专名「目代号」。

**R5 · §1.3 P-c 右侧边界（数据之后补）**
- 句式右侧取"去掉前导虚词（是/只/喝/不/很/的/叫）后的名词核"；去完长度 <2 则不抽。
- 补因：§6 例三我预期抽到 P:美式，实现把"是只喝美式"整段当候选后被函数词过滤而抽不到；两条路径都得到 supported，但抽取清单不同，必须写死。

（以上五条全部是**数据之后**追加，没有一条修改原条文；对已跑四例/三边界/交叉检验的结论无影响，因为四例的 verdict 在两种读法下相同。）

### 9.2 数据之后追加的修订（2026-10-25，产品级接线暴露 A 族两侧抽取不对称）

**R12 · A 族（车牌/型号）源侧与答案侧必须用同一抽取器与同一归一化**
- **缺陷形状（两侧不对称）**：答案侧用 `RE_PLATE` 抽到「浙B-3F19K」→ key `浙B3F19K`（**含省份字**）；
  源侧 `source_profile` 只跑 `RE_CODE` → `prof["latin"]` 里只有 `B3F19K`（**丢了省份字**）；
  `a_hit` 是单向包含 `key in latin` ⇒ 不命中 ⇒ 「块里有车牌、模型也答对」被判 unsupported，
  产品把**正确答案**改写成「记忆里没有记录车牌号。」。这是**误判**，正是 §5「漏判优先于误判」要防的方向。
- **修法（冻结）**：**在抽取侧修对称性** —— `source_profile` 对源文本跑与答案侧**同一套** A 族抽取
  （`RE_PLATE` + `RE_CODE`，同一个 `alnum_key` 归一化），可另开 `prof["plate"]` 桶。
  **不得**把 `a_hit` 改成双向包含来糊过去（那是在匹配点打补丁，两侧抽取仍不对称，换个分隔符或省份字还会换形状复发）。
- **禁止事项（可核）**：修完的 `a_hit` 函数体不得出现双向包含（`latin in key` / `key in s or s in key` 之类）；
  且本次改动的 diff **不得触及 `a_hit`**（用 diff 断言，见 §7 验收清单）。
- **新增自检**：**抽取侧对称性自检** —— 取任意块正文，分别用「答案侧抽取器」与「源侧 profile 构造器」处理，
  A 族的 key 集合必须**相等**（写成断言，不许人工目测）。
- 补因：`plate_main` 实测 `unsupported`（run_m5_grounded.json 的 acceptance[1]=false），而块正文里逐字含该车牌。
- 判据自身的缺口：§2.2 只规定了「怎么比」，**没规定两侧必须用同一抽取器**。R12 补的就是这一条。

### 9.3 数据之后追加的修订（2026-10-25，R12 修复复核后）

**R14 · A 族已知缺陷登记（本轮不修）+ 修法方向（须单独评审）**
- **缺陷**：`RE_PLATE = [\u4e00-\u9fff][A-Za-z][-· ]?[A-Za-z0-9]{4,6}` **不要求分隔符**，且前缀是**任意 CJK 字**。
  于是「您的车牌是B3F19K。」被收成 key `是B3F19K`、「车牌号 B3F19K。」收成 `号B3F19K`；两侧都拿不到这个 key ⇒ 判 `unsupported`。
  （注意：紧邻 CJK 后接**省份字+字母**时不受影响 —— `是浙B-3F19K` 仍从「浙」起匹配成 `浙B3F19K`；只有**裸 body 紧邻 CJK** 才会被吞。）
- **方向评估**：安全侧（弃答，而不是把编造判成命中），且本轮 `before == after`。按 §5「漏判优先于误判」，**本轮不修、只登记**。
- **修法方向（将来）**：把前缀从「任意 CJK」收成**省份/号牌前缀封闭词表**（京津冀晋蒙辽吉黑沪苏浙皖闽赣鲁豫鄂湘粤桂琼渝川贵云藏陕甘青宁新 + 使/领/警/学），
  这样 `是B3F19K` 不会命中 `RE_PLATE`，落到 `RE_CODE` 的代号类 ⇒ key `B3F19K` ⇒ 与源侧 latin 里既有 body 相等 ⇒ **supported**。
- **但这不是"顺手改"**：它会把 c1（`您的车牌是B3F19K。`）的裁决从 `unsupported` **翻成 `supported`**，属于**判据变更**，
  必须走 D 条的前后对照表 + 单独评审，不得夹在别的修复里提交。
- **一条开放问题（判据尚未定义）**：答案只给裸 body、缺省份字时，正确裁决到底是 `supported`（单向规则：答案缺）还是 `unsupported`（答案是另一个无效值）？
  两者都能自圆其说。在定义清楚之前，**按 `unsupported` 记**（安全侧），并在修 R14 之前先把这条定义补上，否则修完会把一个未定义的口径固化成代码行为。
