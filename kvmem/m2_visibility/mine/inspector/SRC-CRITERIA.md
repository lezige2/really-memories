## 1 不变量（不可协商）

- **I1 唯一副本**：一条源的 text 全仓库只存 1 份（库里那行）。其它出现必须是**引用**（id + sha）或**显式 fixture**（带与注册表比对的 sha 断言）。
- **I2 可校验**：读取时重算 sha256(text) 与 source_hash 比对，不等即**显式失败**。不许「警告后继续」。
- **I3 只读消费**：消费者只读源文本，永不回写（与块文件同一条纪律）。
- **I4 缺源必须显式**：缺失或校验失败 ⇒ 抛错，或降级为 **undecidable**。**绝不允许空串当源**，绝不允许 supported。
- **I5 身份稳定**：一条源 = 一个 id；name 唯一且不复用；改名不新增行（否则指它的块全体孤儿）。
- **I6 禁止用字符串表达来源**：provenance 必须是 (source_id, sha256)；不许是 module.attr 或「m4.memory_source.text」这种字面表达式。

## 2 权威源库规格

表 source：id INTEGER PK ｜ name TEXT UNIQUE NOT NULL ｜ label TEXT ｜ text TEXT NOT NULL ｜ sha256 TEXT NOT NULL（CHECK 长度 64）｜ created_at。
- 写入：put_source(name, label, text) **幂等**——同 name 同 sha ⇒ 不新增行；同 name **不同 sha ⇒ 拒绝**，要求显式建新版本。
  （**不许静默覆盖**：静默改源会让所有指它的块悄悄分家，这是最隐蔽的一种失真。）
- 读取：get_source(name|id) 内含 I2 校验；另提供 get_source_or_fail 供消费方使用。
- 删除：仍被块引用时**拒绝**（与 BlockLeases 同一条纪律）。
- 变更：text 改动 ⇒ 新 id 或显式 version；旧块标 stale，**不许直接改 text 后当没事**。

## 3 消费方读法（C1-C3 是 lead 三条；C4-C6 我补）

- **C1 两段链都要对**：注册表行 → block.source_text → M5 源侧 profile，**任何一段 sha 不等 ⇒ 显式失败**。
  只断言「M5 源 == 挂载块源」不够——那只证明两者同源，不证明它们来自权威副本。
- **C2 缺源 ⇒ undecidable，绝不 supported**（与 R13-C② 同源：拿不到权威源时，任何「源里有」的判定都是编造）。
- **C3 M4 的 evidence_span 必须能在注册表文本里定位**：span 落在 text 内**且切片逐字相等**；不得只与自身副本自洽。
- **C4 M4 memory_source 是分段派生层**：每行必须带 registry_source_id，且断言行文本是注册表文本的**逐字子串**；注册表变了而派生层没重建 ⇒ 必须报 **stale**。
- **C5 工具侧字面量退场**：diag_place / eval_heldout / eval_retrieval / kvdrift 的平行文本，要么改读注册表，
  要么保留为 fixture 但**必须断言其 sha 与注册表一致**；**字节不一致的不许悄悄统一**，必须逐条列出决策（canonicalize / 标 fixture-variant 并记录差异）。
- **C6 text_origin 改写**：现值「m4.memory_source.text」属 I6 违例，必须改成 registry:name@sha16 形状，且能被解析回查注册表。
  它是**溯源字段**，改动必须在 diff 里显式声明。

## 4 (a) 两层合不合并 —— 裁决：**不合并**，但规定权威方向

- 层 1：**全局权威源注册表**（事实文本的唯一副本）。
- 层 2：**M4 项目级 memory_source**（段级行 + 句级行）＝ 层 1 文本的**分段派生**，不是第二个源。
- 规则：层 2 每行 registry_source_id 非空 + 子串断言（C4）；**层 2 不得出现层 1 没有的文本**（出现即等于第二种源）。
- 理由：合并会把「分段/切片」这件实现细节塞进注册表，让注册表变成 M4 的内脏；而不合并只要把方向写死，就不会长出两个源。
  这与 R13-C② 是同一条纪律：**派生数据不得冒充源**。

## 5 (b) 纯重构还是判据变更 —— 裁决：分阶段，不同结论

- **Stage 1**（建表 + 双写一致性断言，消费方一行不改）：**纯重构**。
  口径：chat.db 两行 source_hash 迁移前后**字节不变** + 既有三问答案 sha 不变（852a5e5e / dacdc1a8 / 46272e43）。
- **Stage 2**（chat.py 改读库）：**纯重构**。唯一真回归 = M2 51 格三问答案 sha **逐字节一致** + 几何 51 / [4045,4096) / gap 0（不用单测替代）。
- **Stage 3**（M5 改读库）：**重构，但必须判据级回归** = 22 行对照表 after **全部等于现版**；任一行变化 ⇒ 视为**判据变更**，停下重新冻结。
- **C5 的 4 个字节不同变体不属重构**：把它们改成注册表文本会改变工具行为与历史结果，**是判据变更**，必须逐条评审，Stage 1-3 不许夹带。

## 8 R15 · conversation 源不得作 M5 源侧（冻结：2026-10-25，1b 之前）

**R15-a 规则（lead 定，我原文冻结）**
- 层 1 增两个**结构性**字段：`text_kind`（`human_memory` | `conversation`）与 `contains_model_turns`（0/1）。
  profile / project = `human_memory` / 0；conv_2026-10-25 = `conversation` / 1。`resolve_origin` 反查必须一并返回 `text_kind`。
- **`text_kind=conversation` 的源只能用于证明「块正文来自何处」（text_origin 回查），绝不得作为 M5 的源侧。**
  M5 源侧只接受 `text_kind=human_memory`。
- 理由（同 R13-C② 同一条病，从「解析值」换成「模型发言」）：对话记录含模型回合，
  若它当 M5 源，模型先前一句「记住了」甚至一句编造都会被当成「源里有」==> **拿自己的产出当接地依据**。
- **安全方向（写死，防止以后被人当缺陷来"修"）**：M5 源侧只取人类发言 ⇒ 有些人类发言不会进 M5 源 ⇒ 相关提问变 `undecidable`（弃答）。
  按 §5「漏判优先于误判」这是**安全方向，有意为之，不是缺陷**。
- 事实依据（我 dump 的）：主块 `blk_conv_2026-10-25_01` 9 行，其中 **2 行是模型回合**（第 1 行「你好！有什么可以帮你？」、第 5 行「记住了。」），其余 7 行为用户。

**R15-b M5 源侧到底是什么（我补，必须有定义，否则 1b 无法实现）**

R15-a 只说"conv 不得作 M5 源"，但没说"那 M5 源是什么"。三种可能，后果完全不同：

- **(a) 人类回合子集（role=user 的行）**：等于把 conv 切一半继续当源。**我否**——它仍是"块正文"的切片，不是可校验的源条目，且无法署名。
- **(b) 人类回合**入库为**摘录行**：层 1 增 `text_kind=human_memory` + `is_excerpt=1` + `derived_from=<conv name>@<sha16>`，
  并要求其 text 是 conv text 的**逐字子串**（断言）。M5 源侧 = 层 1 的 `human_memory` 行（含摘录）。**我裁定：取 (b)。**
- **(c) conv 一律不作源、也不建摘录** ⇒ M4 产品路径**没有**合法 M5 源 ⇒ 每一个硬事实都只能 `undecidable`。

**为什么必须现在定 (b)**：若取 (c)，`plate_main` 会从 `supported` 翻成 `undecidable` ⇒ **我上轮给的「M5 产品可用：通过」当场失效**。
这不是反对 (c) 的理由，而是说**这个选择必须显式做、写进判据**，不许在 1b 里悄悄漂过去。
我选 (b)：它既满足 R15-a（conv 不作源），又让可校验的人类事实有署名条目，且摘录带 `derived_from` + 逐字子串断言，符合 §4「派生数据不得冒充源」。

**R15-c 由此对 I1 的精确化（必要，否则 (b) 会与 I1 冲突）**
- I1 的原话「一条源的 text 全仓库只存 1 份」对**段落级源**成立；**摘录行允许与其容器共享字节**，但必须同时满足：
  ① `is_excerpt=1` 且 `derived_from` 非空；② text 是容器 text 的逐字子串（断言）；③ `assert_unique_texts` **不得**把摘录当作容器的重复副本（判重只在同 `text_kind` 且同 `is_excerpt` 层内做）。

### 8.2 R15-g/H · 声明的可推翻性 + 「覆盖」与「可检索」必须分开数（冻结：2026-10-25，1b 之前）

**口径裁决（lead 定 A，我原文收编并落成可判形式）**
- **层 1 摘录（源侧）= 全部人类回合（7 行）** —— 它决定「一句话能不能支撑答案」。
- **层 2 事实 + 检索索引（4 条）** —— 它决定「一个问题能不能被命中」。
- ⇒ 报告固定给**五元组**：`(user 行数=7, assistant 行数=2, 层1 摘录行数=7, 被层2事实覆盖的行数=4, 可检索事实数=4)`。
- 并必须写明一句：**未覆盖的 L1「你好呀！」/ L7「帮我查下明天天气。」/ L8「谢谢，就这样吧。」是「不可检索」，不是「不可支撑」。**
  这两件事一旦混用，就会长出两种错误：「明明是人类说的却 undecidable」被当实现 bug；「undecidable」被当源缺失来"修"。
- **派生纪律**：报告里不得把「未被覆盖」写成「缺失源」「无源」；不可检索只报 `retrieval_miss`，源缺失只报 `source_missing`。

**R15-g 角色声明必须可被推翻（lead 定，我落成条文）**
- 若发现某行角色标错：**改声明 ⇒ 该容器的摘录集整体失效并重建**（与 R15-e 同等处理）。
- 必须留四元组记录：`(旧声明 sha16, 新声明 sha16, 原因, 时间)`，以及旧摘录行的处置（标 stale 或删除，二者明示其一）。
- **禁止就地 `UPDATE role` 字段了事** —— 那样「声明」与「摘录」之间会出现**无记录的错位**：
  声明说这行是助手，摘录却还留着它当源，而库层面没有任何东西会报错。这与今晚反复出现的静默变更（静默覆盖源、静默改行号）是同一条病。
- 机器可判形式：声明变更后，`assert_unique_texts` 与跨层可追溯断言（R15-f）必须对**新旧两份摘录**都能给出确定的结论（旧的 stale、新的通过），不许两者都"看起来正常"。

**§8.2-a 附记（数据之后追加）：我实测了「源侧从 9 行缩到 7 行」是否改变裁决 —— 结论是不改变，且这是可复算的**

- **推广**：凡"漏写即放行"的字段都是同类缺陷。它比"写错"更危险，因为没有字节层报错，只有在事后被断言抓住（本例正是这样被抓住的）。

### 11.4 I8-b · 相邻那一列：默认值方向 + **闸门根本没读它** + 强相关的正确形式（冻结：2026-10-25）

**lead 指出的第二处**：`contains_model_turns INTEGER NOT NULL DEFAULT 0` —— 漏写得到「不含模型回合」，同一条病。
我核了建表 sql：**CHECK 为 False**（`text_kind` 与 `contains_model_turns` 都没有 CHECK），与我先前实测一致。

**我另发现一件更要紧的**（比默认值更直接）：`assert_m5_source_allowed` 的实现**只判 `text_kind`**：
```
if kind != "human_memory": raise SourceNotAllowed(...)   # turns 只被拼进报错文案
```
⇒ 一行 `text_kind=human_memory` + `contains_model_turns=1` 会**通过闸门**。也就是说这一列目前是**装饰性的**，
它被写进返回值、写进报错消息，却**没有任何一处用它做决定**。这属于 I7「两处各存一半真相」——现在是"一存一存却互不校验"。

**lead 给的二选一我都不取，理由如下（这是我与 lead 唯一的判断分歧，请裁决时看理由）**

- **不取 (A) 纯派生（把该列删掉、由 `text_kind` 推）**：因为 `conversation ⇒ contains_model_turns=1` **不成立**。
  一份纯人类发言的会话记录，`text_kind=conversation` 而 `contains_model_turns=0` 是**合法事实**；
  强行派生会让这一类被错标成"含模型回合" —— 对闸门而言是安全方向（都要排除），但它把这个字段变成永远的真值替身，
  以后再有人拿它做别的事（比如报告里"这段对话是否含模型发言"）就会得到假值。**用一个假字段换掉两个可能不一致的字段，不是修好。**
- **不取 (B) 双向 CHECK（`conversation ⇒ turns=1`）**：同上，会禁止一行合法数据。
- **取 (C)：方向一，默认值翻向拒绝态，闸门三条件并列。** 三条一起，才能同时满足"单一真相""fail-closed""不放行假人类记忆"：

**I8-b 条文**

1. **默认值各自 fail-closed**：`text_kind DEFAULT 'conversation'`；`contains_model_turns DEFAULT 1`。
   （漏写 ⇒ `conversation` / `1` = 双重拒绝态；而今天的默认是 `human_memory` / `0` = 双重放行态，两个方向全错。）
2. **只加逻辑成立的那个方向约束**：`CHECK (NOT (text_kind = 'human_memory' AND contains_model_turns = 1))`。
   即「含模型回合的文本，绝不能被声明为人类记忆」——这一条是我们真正要防的；反方向（纯人类会话 turns=0）必须允许。
3. **闸门必须并列判三项**：`text_kind == 'human_memory'` **且** `contains_model_turns == 0` **且**（若 `is_excerpt=1`）`derived_from` 非空且逐字子串成立。
   任一项不满足 ⇒ `SourceNotAllowed`。当前实现只判第 1 项，**必须补齐后两项**。
4. **可判证据三条**（缺一不算关闭）：
   - (i) 只用老列的 INSERT（不写这两列）⇒ 读回 `conversation` / `1`；
   - (ii) 人造一行 `human_memory` + `1` ⇒ **被 CHECK 拒**（若实现选触发器/应用层，则必须在该路径上被拒并给出异常类型）；
   - (iii) 人造一行 `human_memory` + `1`（绕过 CHECK 直接改副本库）⇒ **闸门必须抛 `SourceNotAllowed`** ——
     这条证明"闸门读了这个列"，比任何默认值都更能说明它不再是装饰。

**若执行者坚持 (A)**：那也只能从**角色声明**派生（`assistant_lines` 非空 ⇒ 1），不能从 `text_kind` 派生；
并且必须同时给出「纯人类会话」这条反例的往返测试（`conversation` + `0` 仍可如实表达）。否则我不接受 (A)。

### 12.1 S3-1 · 追溯改为行级（我实测支持）

- 我实测：`joined in container` = **False**；7 行逐行 `in container` = **True**（行号 1,3,4,5,7,8,9）。

### 12.2 S3-2 · origin 解析器唯一实现 + 语法冻结（含 lead 收紧一、二）

**语法**（三段，两处 `@`、一处 `#`）：
`<kind>:<container>@<container_sha16>#<L 行号表>@<joined_sha256>`

- **唯一实现**：`format_origin()` 与 `parse_origin()` 必须是同一文件里**相邻的**一对，writer 只准调 format，reader 只准调 parse；
  禁止「写时格式化、读时正则」两套。冻结时把两者的 `file:line` 记进验收。
- **重组段只接受 64 hex，拒绝 16**（这类 origin 形态是全新的，没有 legacy 需要兼容；接受 16 等于「任意 16 字符前缀相同即过」）。
  容器段仍是 16（它只是版本标识，强度由块侧 sha 与行 sha 兜底）。
- **行集顺序敏感**：比序列不比集合。必须同时满足 ① 升序 ② 互异 ③ 全在容器行号范围内 ④ `joined.split(换行)` 长度 == len(行号表)
  ⑤ 第 i 段与容器第 idx 行**逐字节**相等 ⑥ 每段 sha256 与 `memory_source_excerpt.line_sha256` 相等。
- 反解还必须：⑦ 用容器 sha16 校验容器未变（R15-e，不符抛 `Stale`）；⑧ origin 的 joined 段 == 该块 `source_text` 的 sha256。
  第 ⑧ 条是我加的：否则 origin 可以指向一串和实际入块文本不同的东西，而两边都「自洽」。
- **负向三测**：`L5`->`L6` 改动（正则能匹配、校验必须失败）、行号顺序打乱（L9..L1）必须拒且报错指明**行集/顺序**不符、
  joined 段写 16 hex 必须拒。
- **触底实测**：我算得 `origin(16/64)` = **139 字符**（`origin(16/16)` 只有 91），与 lead 同值。
  必须有一条「完整落库、读回**逐字节**相等」的实测（不许 START 前缀、不许取前 300 —— 今晚已经出过一次截断）。

### 12.5 S3-5 · `synthetic` 绑死前缀 —— 但 lead 给的 CHECK 有一个 NULL 洞（我实测）

我实测 SQLite 行为（表带 `CHECK ((origin LIKE 声明合成前缀) = (synthetic = 1))`）：

    PASS (None, 0)      <- origin 为 NULL 放行
    PASS (None, 1)      <- origin 为 NULL 放行
    PASS (registry:x, 0)
    PASS (declared_synthetic:y, 1)
    REJECT (declared_synthetic:y, 0)
    REJECT (registry:x, 1)

⇒ **CHECK 表达式求值为 NULL 时视为通过**。origin 为 NULL 的行会同时绕过 D3-1 与「非空」要求（若非空只写在应用层）。
必须写成：`CHECK (origin IS NOT NULL AND ((origin LIKE 声明合成前缀) = (synthetic = 1)))`，另加 `CHECK (synthetic IN (0,1))`。
并加负向：**origin 为 NULL 必须被 CHECK 拒**（当前形式会放行）。
`plate_main.synthetic=0`、`plate_ablated.synthetic=1`（我实测 noplate 块现状：`source_text_len` 113、sha16 93332bde804698bc）。

### 12.12 三条通则（2026-10-25 冻结，来自 0-a / 0-c / 账本自检三次撞击）

**通 1 · NULL 等于「约束没生效」，不等于「约束满足」**
- SQLite（以及任何三值逻辑）里，CHECK 表达式求值为 NULL 时**视为通过**。
- 实测证据：`CHECK ((origin LIKE 声明合成前缀) = (synthetic = 1))` 对 `(None,0)` 与 `(None,1)` 均 **PASS**。
- 规则：凡 CHECK 涉及「列 与 列」或「列 与 常量」比较，**必须显式排除 NULL**（`col IS NOT NULL AND (...)`）。
- 推论：任何"某列非空"的要求，**只写在应用层等于没写**；DB 层必须也有一份，且那份也要被负向测过。

**通 2 · 凡新增断言，必须同时给一条能让它失败的输入**
- 没有负向输入的断言，等于一段永不执行的代码；它不减少任何风险，只增加账本的行数。
- 这条同样适用于**自检本身**：账本自检（键数 vs 独立判据数）也必须有一条"注入别名 ⇒ 必须失败"的负向。
- 这是 I7 的推广：I7 管「两处各存一半真相」，本条管「一处根本没在管」。

**通 3 · 计数与度量必须附「调用形态」**
- 与「查询语句原文 + 返回值」「哈希附定义」并列：报一个数，必须同时给出**入参的类型与结构**。
- 实证：`source_profile(texts)` 收列表；传字符串会逐字符遍历 ⇒ `latin/plate/props` 全空，而**结论方向恰好不变**。
- 这类错误最难被抓：它错的是量的定义，不是结论的方向；任何只看结论的复核都会漏掉。

### 12.13 验收单格式要求（2026-10-25 冻结）

**格式 A · CHECK 与负向一一对号**
- 每一个 DB 层 CHECK（以及每一条触发型约束）必须在验收单里登记「哪条负向用例覆盖了它」。
- **缺号的 CHECK 视为未验**，不得计入通过项。理由：一条没人测过的 CHECK，与一句注释等价；
  而读者看到 CHECK 会以为它已经被验证过。
- 已存在的 CHECK 清单（`memory_source`）：合法值三连（text_kind / contains_model_turns / is_excerpt）、
  `NOT (text_kind=human_memory AND contains_model_turns=1)`、`is_excerpt=0 OR derived_from IS NOT NULL`；
  Stage 3 将新增 `origin IS NOT NULL AND ((origin LIKE 声明合成前缀) = (synthetic=1))` 与 `synthetic IN (0,1)`。
  每条都要有号。

**格式 B · 账本自检的两个数必须同时打印**
- `key_count` 与 `distinct_judgements` 同时输出，不等即失败；并附 `retired_keys` 清单（退役项不得计入键数）。

**通 4 · 不得比对「渲染出来的字符串」，只比对结构或取值**
- 实证（我在真实提交上抓到的红态）：`ledger_selfcheck` 用 `ast.unparse` 渲染来源表达式，输出 `res['x']['ok']`（**单引号**）；
  而负向断言里写死的是 `res["x"]["ok"]`（**双引号**）⇒ 断言恒假 ⇒ `14_ledger_selfcheck_catches_alias=False` ⇒ 整体 `pass=False`。
- 这不是笔误的孤例，是「两处各存一半真相」在**字符串格式化层**的复现：生产端负责渲染，消费端硬编码同一格式，
  两者一旦不同就是静默错位（此处恰好被断言抓住，因为它比的是精确相等）。
- 规则：凡比对由格式化函数/序列化函数产生的字符串，必须改为比对**结构或取值**（如 `list(dup.values()) == [[...]]`）。
  现已按此修正，并有注释说明原因 —— 该注释必须保留。

**附：这条红的正面价值**
- 它证明负向测试**在真实提交上确实能变红**，不只是在我构造的探针里。
- 记录：`14= False` 曾真实出现于 04:4x 的一次中间产物中，随后修正；修正前后我都独立复跑过 `ledger_selfcheck`。

### 12.14 通 5 与纪律族名（2026-10-25 冻结）

**通 5 · 新增断言必须给一条能让它失败的输入，且失败时须断言失败的具体形状。**

适用范围：**所有验收断言**，不只负向。要求举例：
- 行序类断言 ⇒ 失败必须说「顺序不符」，不得只说「校验失败」。
- 编码长度类断言 ⇒ 失败必须说「需要 64 hex」，不得只说「格式错误」。
- 闸门类断言 ⇒ 必须说清是**哪一条判据**拒的（`text_kind` / `contains_model_turns` / `derived_from`），不得只抛「不允许」。

理由：**报错形状是断言的一部分**。报错含糊时，人只能靠猜；而猜出来的修复通常修错地方。

**三种坏账本与各自的挡法**（今晚实测归纳）：

| 坏法 | 实例 | 靠什么挡 |
|---|---|---|
| ① 永远为真 | 投毒测试（常量已不存在，测什么都过）| 通 2「必须能给失败输入」|
| ② 永远为假 | 断言写死 `res["x"]["ok"]` 而生产端 `ast.unparse` 出单引号 ⇒ 恒假 | 双边（负向 + 对照）|
| ③ 红得不对 | 只要求 `ok is False`，不查是哪一组重复 | 通 5 的「红得对」（值比对）|

**纪律族名：结论须自带复算材料**。三条是同一条的三次变形 ——
计数带查询原文与返回值；哈希带定义（序列化/列集/顺序/编码）；失败带形状（哪一条、哪一组、期望 vs 实际）。

### 12.15 四态词表、失锚窗口、锚作废字段、重锚前置检查（2026-10-25 冻结）

**四态词表（项目级，不许混用）**

| 状态 | 含义 | 本轮实例 |
|---|---|---|
| **通过** | 判据已验且产物锚对得上 | Stage 1a/1b、Stage 2、I8-C |

- 可回填历史锚（M4 三锚、`_m5db` 内容哈希那次），非阻塞但必须写进格式。

- 理由：Stage 3 只改「喂给 M5 的源文本」，不改 KV 内存。若块文件变了，说明被误伤；
  此时建立的锚会"对得上但对象错了"，比锚过期更麻烦。
- 规则：块文件一变 ⇒ **停下**，不许把变化"顺便解释成正常"，也不许在这个产物上建新锚。

| 列 | 期望 |
|---|---|
| `source_text` | **预期变**：`source_text_len` 127 -> 110 |

`invalidated_anchors: expected_by=none 计数 = N`，N>0 时必须列出是哪几条。
今晚已知命中一条：`876deaa3`（lead 事后判死又撤回，事前无任何声明）⇒ 回填时记 `none`，不许攀附其它声明。

### 12.18 `gate_inside_selection` 定位口径（裁定，2026-10-25）

执行者把选源抽成 `select_m5_source()`、闸门在其中，因此原「闸门必须在 `ensure_db()` 函数体内」的口径需要改。
**裁定：判据以「谁返回被准入的源」为准，不绑函数名。** 三层同时成立才算过：

1. **结构（AST）**：存在对闸门（`assert_m5_source_allowed` 或其唯一包装）的调用，且该调用位于**返回被准入源清单的那个函数体**内（今天即 `select_m5_source`）。
   验收必须打印该调用的 `file:line`。
2. **可达性（AST 调用图）**：该选源函数必须从公开入口（`ensure_db` / bridge 入口）**可达**；`ensure_db` 的检查保留，但只作可达性用，不再要求闸门本体在其中。
3. **运行时拒绝（权威）**：静态结构只能证明"写了调用"，不能证明"没有旁路返回"。所以必须有一条运行时测试：
   **把注册库置为不可用 / 让某块无合法源 ⇒ 进程必须拒绝**，而不是返回一个未经闸门的清单。
   报错须说清是哪一条判据拒的（通 5）。

理由：函数名会变、调用会被抽出，而「返回前后没有闸门」这件事不变。判据绑函数名会让**重构时判据先坏**，
绑错误文案则会让**改名时判据先坏**；只有"返回点 + 可达性 + 运行时拒绝"三者不随重构失效。

### 12.19 两处 fail-open（并入验收，2026-10-25）

**A · 注册库拿不到 ≠ 不设防**
- 现状：`regcon = sqlite3.connect(REG_DB) if os.path.exists(REG_DB) else None`；随后 `if regcon is not None and ...` 整条守护被跳过。
- 后果：`REG_DB` 路径失效（路径错/被移走）⇒ 所有块走合成分支 ⇒ **全部豁免闸门**，而唯一守护同时失效。
  这不需要任何人做错事 —— 而"路径失效"今晚已经发生过（README 锚、`_before` 副本）。
- **判据：拿不到注册库必须等于拒绝（fail-closed）**，异常须指名"注册库不可用"，不得静默降级。
- 可判证据：把 `REG_DB` 指向不存在路径 / 改名为临时文件 ⇒ 进程必须拒绝，且报错含路径与原因。

**B · `except sqlite3.OperationalError` 太宽（违反通 5）**
- 现状：列改名、表缺失、db 损坏全落进"消融库没有该列"的豁免分支。
- 今天靠下游兜底（层 1 有名字 ⇒ 抛 `OriginError`）才没出事，但**报错形状是错的**：
  主库 schema 事故被报成「layer-2 row 未链接，拒绝标为 declared_synthetic」⇒ 下一个人会照报错去跑 `m2_link --apply`，
  **把一次 schema 事故修成一次误链接**。
- **判据：「这是不是豁免路径」必须由 schema 的正面证据（`PRAGMA table_info` 是否真的没有该列）决定，不能由一次异常决定。**
  异常只说明"某事失败了"，不说明"这是合法合成源"。
- 可判证据两条：(i) 消融库确实没有该列 ⇒ 走豁免且报错文案说明"schema 无此列"；
  (ii) 主库存在、但该列被改名/表被删 ⇒ 必须抛**与豁免无关的**错误（指名 schema 事故），不得进入 `declared_synthetic` 判定。

### 12.20 旧产物保全与两份产物分离（常驻规矩，2026-10-25）

**规矩**：任何会覆盖已验收产物的运行，运行前必须先把旧产物复制到 `_before/<name>@<sha16>`，
并登记 `(source name, old sha16, copy time, 复制者)`。
理由：**锚只能证明「曾经是什么」，不能保存「曾经是什么」。** 本轮 `run_m5_grounded.json` 从 `d97cdfdcbd6c6d3d` 被覆盖为 `24fb336b1eb2734d`，
且该 json **从未入 git** ⇒ 旧裁决本体已丢，before 侧只能靠运行前偶然落下的 `_stage3_pre.json`（`9500f1c7c59c118f`，04:46:38）重建。
**运气不是流程。**

**两份产物必须分开，不许合并成"一份预登记"**：
- `PREREG-STAGE3-11ROWS.json`：标 `authored_after_run: true`，逐行给期望与**期望的依据**（7 行给代码行号，4 行给散文/提交出处）；
- `before-reconstruction`：标 `reconstruction` + provenance（`_stage3_pre.json @ <sha16>`）。
倒签的预登记 = 用结果当期望，是纪律六的第三种失败。

**附：before 侧有两条轴，不得混谈**（我复算确认）
- **代码轴**（`load_pre_module()` = `e172aca` → 当前）：`plate_main` 由 `unsupported` 变 `supported` —— 这是 R12 修复的效应。
- **源文本轴**（容器 127 → joined 110，同一版代码）：我复算 `plate_main` **supported → supported**，`home_main` **supported → supported**；7 条探针全部 before==after 且全中期望。
⇒ 新 run 里的 `verdict_before` 属**代码轴**，不能当 Stage 3 的 before 侧；Stage 3 的 before 侧只能用重建结果。

### 12.21 纪律七（字段名带轴）、`_before` 登记、证据强度分级（2026-10-25 冻结）

**纪律七 · 字段名必须携带它的轴/坐标**
> 凡同一个量在不同产物里可以由不同自变量产生，**字段名必须写出自变量**（例：`verdict_axis = code | source_text`），
> 否则两个产物之间任何一次比较都会静默换成另一个因果。

实测来源（本轮最险的假结论入口）：
- 代码轴 `e172aca` → 当前：`plate_main` `unsupported → supported`（＝ R12 修复的效应）；
- 源文本轴 127 → 110（同版代码）：`plate_main` `supported → supported`（＝ Stage 3 自身效应为零）。
同一个 `verdict_before` 在两份产物里指不同轴；拿错一次就会得出「Stage 3 让 plate_main 从不支持变支持」——
**而这个假结论的形状恰好是"一次成功的改进"，最难被质疑。**

**`_before` 副本登记形式**：`_before/<旧文件>@<旧 sha16>` + `_before/REGISTER.json`，每条
`{source_name, source_sha16, copy_time, copyist, reason}`。`reason` 必填：
**为什么在那个时刻复制** —— 否则半年后看到副本，仍分不清是「运行前预防」还是「事后补救」。

**证据强度分级（报告必须逐项标注，不得合并）**

| 级别 | 含义 |
|---|---|
| **R · 重算** | 我在本地独立跑出该值（可信度最高）|
| **C · 构造性覆盖** | 该行依赖的输入未变，由可复算的元数据论证（如文件 mtime 早于镜像 + 正文逐字节相等）|
| **A · 锚定转录** | 我只核对了产物 sha 与自述，未独立重算 |
| **S · 仅自述** | 只有对方声称，我没有对应证据 |

本轮实例：7 条探针 + `plate_main`/`home_main` = **R（重算 9 行）**；
两条 ablated = **C（构造性覆盖 2 行）**（辅助库 sha `c44abc2547aad560`、mtime 03:38:01 早于 pre 镜像 04:46:38、正文 113 字符与 pre 镜像逐字节相等）。
**报告必须写「重算 9 行 + 构造性覆盖 2 行」，不得合并成「11 行全部重算」。**

### 12.22 强度格不留空 与「缺口先记」（2026-10-25 冻结）

**强度格不许留空**：验收单任一行必须点一个字母 **R / C / A / S**。无证据即 **S**，不许省略。
理由：**省略与 S 在纸面上看不出区别**，但一个是"没证据"，一个是"忘了填"。

**缺口先记**：所有已知缺口（未验项、只到 C 级的项、无法重算的项）必须在**判据冻结时**写进验收单，
不得等交付时补。理由：**事后补充的形状永远比事前声明好看** —— 所以必须在**没有动机的时候**写下来。
本轮实例：空 db 行为「未验」、两条 ablated 行只到 **C 级**，均在 Step 1 验收单草案里先行登记。

**页眉写成操作指令**：「两轴不同」是事实陈述，读者会点头跳过；
「**禁止跨轴比较**」是操作指令，他在真要比较时会挡住他。

### 12.23 纪律八、三处独立拒绝点、报错拆分（必修）（2026-10-25 冻结）

**纪律八 · 报错里藏着下一步动作的，必须当成判据来审**
> 凡报错文案含「下一步动作」，要么该动作在**它能触发的所有情形**下都正确，要么该报错**不可达**。两者必居其一，没有第三种。

依据：**入口可以被断言，文案只能被阅读** —— 而读的人若只有文案，就只能照文案做动作。
今晚两个实例：`m2_link --apply`（需拆）；`SCHEMA ACCIDENT`（做对了：它触发的所有情形动作都是"停下来查 schema"）。

**豁免的三处独立拒绝点（实测，非推理）**

| # | 拒绝点 | 依据 | 探针 |
|---|---|---|---|
| ① | 路径声明（`m4db == ablate_db`）| 声明 | B4（真消融库但不声明 ⇒ 拒）|
| ② | schema 观测（`PRAGMA table_info` 无该列）| 结构 | B1（列改名 ⇒ SCHEMA ACCIDENT）|
| ③ | 层 1 存在性（名字在层 1 就不许标合成）| **数据（另一个库）** | B2（声明了仍被拦）|

③ 的输入与 ①② 完全无关，因此这是 **I7 的正确形态**：不是"一个信号被两种原因产生"，而是"多个独立信号，不一致即拒"。

**报错拆分（必修，不是可选）**

唯一能走到「run m4_layer2_link --apply」的组合是：**声明=True + 列缺失 + 名字在层 1**（误把主库声明成消融库）。
不能"在后面补一句"，必须**拆成两条独立报错**，因为两种情形需要的动作不同：

- 情形 1：名字在层 1 存在 + 未链接 + 该库**未被声明**为消融副本 ⇒ 动作 = 跑 `m2_link --apply`（保持现有文案）。
- 情形 2：名字在层 1 存在 + 该库**被声明**为消融副本 ⇒ 动作 = **修正 `ablate_db` 声明，不是链接**。
  新错误须写明：该库被声明为消融副本，但其行 `%r` 在层 1 存在 —— 声明本身有误（检查 `ablate_db`）。

理由：**一条报错只能指向一个正确动作**；两种情形共用一个消息，消息必然对其中一种是错的。
而例外恰好是最容易犯的错（复制一行改路径）。

**验收方法（R 级）**：6 个运行探针见 `mine/inspector/GATE-AB-PROBES.md`；拆分后须新增第 7 个探针 ——
误声明组合 ⇒ 必须抛**情形 2 的新错误**，且**不得**在文案里出现 `m2_link --apply`。

### 12.24 断言的针必须取自产物；住户与过客；循环期望（2026-10-25 冻结）

**纪律九 · 进入匹配器/断言的字符串必须从产物里复制**
> 凡要进入匹配器/断言的字符串，必须从产物里复制，不得从任何人的转述里复制。
> 转述可以出现在散文里，但**必须显式标为转述**，且**永不得充当断言的字面量**。

后果的不对称：散文里的转述只是不够准；**断言里的转述是一个会静默失败的测试** —— 它红的时候看起来像"被测对象坏了"，而坏的是针。
本轮实例：真实字面量 `m4_layer2_link.py --apply`，转述简写成 `m2_link --apply`（长得像真字面量），断言因此恒假；
若当时按"实现坏了"处理，就会**把正确的代码改成符合错误转述的样子**。

因此「红得对」含两层：**红的形状对，红的位置也要对**。

**住户与过客**：`raise` 的文案是过客，`origin` / `note` / 自述字段是**住户**（会被存进库、比任何一条报错活得更久）。
**住户的门槛应更高，不是更低。** 纪律八（含动作的文案即判据）对住户同样适用。

**纪律十 · 期望不得取自它要预测的那个产物（循环期望）**
- 若某行的 `expected_*` 来自**同一个观测里读出的值**，则 `matches_expected` 恒真 —— 它不是结论，是同义反复。
- `expected_basis` 必须是**冻结于实现之前、且与观测产物无关**的可定位来源：判据 §号、代码字面量（`file:line`）、或可 `git` 定位的提交。
- 落实检查：`expected_basis` 里**不得出现承载观测值的那份产物名**。

本轮实例（我在 `PREREG-STAGE3-11ROWS.json` 里查到）：
- 7 条探针：`expected_basis = "m4_verify_grounded.py PROBES expected_after literal"` ⇒ **合法**（代码字面量，`04:03` 早于 Stage 3；我逐条比对，与代码期望**零不符**）。
- 4 条产品行：`expected_basis = "run_m5_grounded.json cases[plate_main].verdict"` ⇒ **循环**（期望取自它要预测的那份 run 的 `verdict` 字段）。
  因此这 4 行的 `matches_expected: true` 是空的；`authored_at > run` 也救不了它 —— 时间戳只能证明"写得晚"，内容仍来自结果。
- **正确写法**：4 行产品例的期望应当是**「不变」（不变量本身）**，依据 = 冻结判据 §12.7「裁决不变」；
  而"值"应取**重建的 before 侧**（我 R 级重算 = `supported/unsupported/…`），不得取 run 的 `cases[*].verdict`。

### 12.25 注释即断言；"不可达"必须被证明（2026-10-25 冻结）

**纪律十一 · 注释里的可判事实同样是断言**
> 代码注释中任何**可判定的事实主张**（"此分支不可达""只在校验后调用""该列一定存在"），
> 必须要么有探针证明，要么删掉 —— 否则它会被下一个人当作背景知识使用。

本轮实例（我实测）：`origin_of` 的守卫分支注释写着
> `# Unreachable by construction: this helper is only called on the linked path ... or on the ablation db`
而我用如下构造**到达了它**：
- `memory_source` 有 `registry_source_id` 列（非消融库）；
- 该行 `registry_source_id` 为 NULL；
- 该行 `name` **不在层 1**；
=> `select_m5_source` 走"名字不在层 1"的返回路径，构造 dict 时调用 `origin_of`，于是进入该分支：
`OriginError: origin_of: layer-2 row 1 has no registry link (source_hash=…): this branch is unreachable from select_m5_source; a caller reached it, so the invariant broke`。

**判定**：
- **行为是 fail-closed**，且报错自述 "a caller reached it" —— 这部分是诚实的，可接受；
- **注释的断言是假的**，这才是危险物：它会让下一个人不去找那个真实缺口（"新 layer-2 行未链接、名字又不在层 1" 是一种**正常会出现的状态**，
  却被报成"invariant broke"）。
- 建议（一行级）：在 `select_m5_source` 里对"rid 为 NULL 且名字不在层 1"显式拒绝，文案说清真实条件；注释同步改正。

**另一条实测（P9，阴性结果也留档）**：`rid` 有值但 `source_hash` 为 NULL ⇒ **不**进入该分支，
而是走容器/摘录路径，得到 `origin = declared_human_turns:conv_2026-10-25@d8c094c1f5fcb8f1#L1,…`。
⇒ 该状态可排除，`source_hash` 缺失不构成该分支的入口。

**"不可达"作为合格解的附带条件**（与 #8 一致）：
宣称某分支不可达的，必须给出**调用点 `file:line`** 或**可复跑的到达尝试记录**；两者都无，则该宣称不成立。

### 12.26 纪律十二（能判定的写成一行）、阴性留档、第四类缺陷命名（2026-10-25 冻结）

**第四类缺陷 · 假注释**

| 类 | 形状 | 为什么不红 |
|---|---|---|
| ① 永远为真 | 断言恒过（投毒测试）| 它红不了 |
| ② 永远为假 | 写死双引号 | 双边挡 |
| ③ 红得不对 | 只查 `ok is False`，不查哪一组 | 红在错的组也算红 |
| ④ **假注释** | **行为正确 + 注释断言为假** | **测试全绿** |

④ 的代价不在今天，在于**阻止下一个人去查**；它是"看起来已经排除"的污染，与 ① 同族：都不红，都让人放心。

**本轮实例（P10）**：`origin_of` 注释称该分支 `Unreachable by construction`，而三条同时成立即可到达 —
① 有 `registry_source_id` 列（非消融库）② 该行 `registry_source_id IS NULL` ③ 该行 `name` 不在层 1。
**而且这三条同时成立是一种正常会出现的状态**（新建 layer-2 行尚未链接、名字尚未进层 1）；
把它报成 `invariant broke` 比注释写错更严重：**读者会以为"这不该发生"，从而不去修根因。**

**纪律十二 · 能判定的东西必须被写成一行，不能让读者去推**

已出现的五处形态（同一元规则）：
1. 四态词表（通过／未通过／按计划未到／失锚（待重跑））—— 状态不必从上下文推断；
2. 证据强度字母 **R / C / A / S** —— "这行验过了"必须点一个字母；
3. 验收单**页眉写成操作指令**（「禁止跨轴比较」而非「两轴不同」）—— 读者不必自己想到要禁止；
4. **强度格不许留空**（无证据写 S）—— 省略与 S 在纸面上不可区分；
5. **`needle_discriminates = needle_live and needle_absent`** —— "针是活的"成为一行，而非从两个 PASS 反推。

**阴性结果必须留档**
- "排除了什么"与"证明了什么"同价，但它**只在被记下时才省下一次重跑**；
- 没记下的阴性结果等于没做过，而且更糟：**下次会有人再花同样的时间做一遍。**
- 本轮实例：P9（`rid` 有值 + `source_hash IS NULL` ⇒ 不进 `origin_of` 该分支，走容器/摘录路径）。

### 12.27 `_before` 双向集合判据、规矩的生效时刻、主张 vs 证据（2026-10-25 冻结）

**两条方向不同的断言（必须分开解释，不能合成一个"齐/不齐"）**

```
① G16 \ {当前} \ S = 0        （git 见过、_before 漏了的）=> 必须为空
② S \ G16           = 允许非空，且每一项必须有 reason
```

**实测（我复核，与 lead 同值）**：当前文件 `d400dfa1c4e95f43`；
`S`（`_before/m5_bridge.py@*`）= `{1a057b0f, 99a0595, b01ab594, e2f40340}`（4 份，16465/17744/18439/18445 B）；
`G16`（git 全部历史 blob 的 sha256 前 16）= 7 个；
`S \ G16` = 3 个（`1a057b0f, 99a0595, b01ab594`）；`G16 \ {当前} \ S` = 6 个。

**`S \ G16` 非空不是异常，是这条规矩在起作用的证据**：那 3 个态**从未进过 git**，`_before/` 是它们存在的唯一记录。
⇒ **`_before/` 的价值不是"备份 git 里有的"，是"接住 git 里没有的"。**

**规矩有生效时刻**：① 的 6 个缺口全部来自规矩引入之前。
⇒ 正确表述：**规矩只能从它被引入的时刻起强制**；引入前的态由 git 单独覆盖，git 是本轮唯一记录。
不写明生效时刻，下一个人会拿它去**追溯要求早期的态**。

**用集合相等，不用计数**：`|S| == 改动次数 - 1` 里的"改动次数"没有定义 ——
提交数 7 / distinct blob 数 7 / 磁盘实际改动 ≥7（因为 3 个态未提交）**给出三个答案**。分母未定义时，任何计数都不构成判据。

**主张强度与证据强度是两个量，不要一起涨**
- 第 ③ 条（期望来源改为独立重建的 before 侧）完成后，#16 的**主张变强**（从"期望=结果"变为"期望=独立重建"），
  但**证据强度不变**（仍是 `R 9 / C 2`，因为我算 9 行的方式没变）。
- 反过来（证据涨而主张不变）也常见。两者混在一格里，读者无法分辨"结论更强了"还是"我更有把握了"。

**记录我自己的错误（原值 + 错因）**：
- 我报"`_before/` 里仍无 `m5_bridge.py` 任何副本"——**原值：4 份**（另 `REGISTER.json` 现 **20 条**，其中 4 条是 `m5_bridge.py`）。
- 错因：我在**一次** `ls` 之后下结论，而副本在我核对之后才落地；这是"**核一次就下结论**"的形状，与今晚反复出现的"锚过期"同族。
- 纪律：**凡"仍无/从未"这类全称否定，必须附核对的时刻与命令**；否则它无法被后来的证据区分成"确实没有"还是"我当时没看到"。

### 12.28 冗余的可观测性、纪律十三、第五类缺陷（期望陈旧）、S3-4 的作用域（2026-10-25 冻结）

**`_before/` 已整体入 git（我复核）**：`.gitignore:45 _*/` + `:101–104` 例外（`!**/m4/_before/`）；
`git ls-files …/_before | wc -l` = **22**，4 份 `m5_bridge.py@*` 全在版本库；`git check-ignore` 对该目录返回 **未忽略**；提交 `efdfedb`（例外+入库）、`d6e03f1`（Stage 3 step 2）、`d5be504`（文档）。

**冗余的真正价值**

> ⇒ 冗余的价值不只是「能恢复」，是**让丢失变成一个可观测的事件**。
> 若无冗余，最糟的不是无法恢复，而是**没有任何东西会因为丢失而变红**。

**纪律十三 · 全称否定必须附核对时刻与命令**
> 凡「仍无 / 从未 / 全部 / 没有任何」这类全称断言，必须附**核对的时刻与命令**。

| 错法 | 性质 | 有没有复查触发 |
|---|---|---|
| 锚过期 | **结论**变旧 | 有（产物一变，锚即失效）|
| 全称否定 | **视野**变窄 | **没有** —— 连"该复查"都不会提示 |

⇒ 全称否定的危害不在它可能错，在于**它把"我没看见"写成了"不存在"**。
（本轮我的实例：报「`_before/` 仍无任何副本」，原值 4 份；错因是一次 `ls` 之后下结论。）

**第五类缺陷 · 期望陈旧（stale expectation）**
| 类 | 形状 | 为什么不红 |
|---|---|---|
| ⑤ **期望陈旧** | 断言仍通过，但**通过的原因已不是它当初指的那个原因** | 通过本身是好消息 |

本轮实例（我自查）：P10 原期望是「到达该分支 ⇒ 注释为假」；第 ④ 条修好后该分支被改成**显式拒绝**，
此时"到达"仍成立，但含义从"注释是假的"变成"这条正常状态被正确拒绝" —— **同一行 PASS，测的是两件事。**
已改为三问：`p10_no_invariant_claim` / `p10_real_condition` / `p10_correct_action`，各自一行。

**规则**：**被测对象改变后，断言必须重核"期望方向"**，不能只看"还是 PASS"。
与 ③ 的区别：③ 是红在错的组；⑤ 是**绿在错的因**。③ 至少有人会读红；⑤ 根本没人去读。

**S3-4 的作用域（`no_todo_stage3`）**

### 12.29 一个字段只回答一个问题；守门布尔须派生；C/R 须由真算产生（2026-10-25 冻结）

**纪律十四 · 一个字段不得同时回答两个以上的问题**
> 若一个字段同时承载「写在哪 / 执行在哪 / 谁核过」，则前两者可以不一致而不被发现，第三者无法从纸面看出是「一次性核对」。

本轮实例：`expected_source` 一个字段被要求回答三件事 ——
① 出处写在 `m4_verify_grounded.py:213–219`（字符串 :114/:141 如此声称）；
② 执行用的是 `run_stage3_before.py:32–40` 的手抄副本（原件**从未 import**）；
③ 谁核过 —— 我 2026-10-25 05:1x 手工比过一次（值等、`key` 原文不等），**不留痕**。
**⇒ 拆成三个字段**：`basis_declared_at` / `literal_executed_at` / `copy_equality_asserted_by`（后者须是断言 id，不是人名）。

**纪律十五 · 任何守门布尔必须由它所守的对象派生，不得写成常量**
> 写死 `False` 与写死 `True` 一样无用；**前者更隐蔽，因为 `False` 看起来像「检查过了，没问题」**。
实例：`run_stage3_before.py:89` `expected_from_tested_artifact: False` —— 若把 basis 改回 `cases[*].verdict`，该字段仍为 False。
要求：由 `expected_source` 派生，并**配一条能让它变 True 的输入**（否则它不是守门，是装饰）。
这是第 ① 类（永远为真）的镜像：永远为真红不了，永远为假也红不了。

**纪律十六 · C / R 必须由「真的算过」产生，不得由标签决定**
实例：`run_stage3_before.py:84` `unchanged_input = (block == ABL)`、`:87` `"grade": "C" if unchanged_input else "R"` ——
字段名说的是「输入未变」，算的是「块名等于消融块名」。两个消融块之一改名仍会被贴 C，而实际可重算。
要求：两侧各算一次，且必须给一条**能让「贴标签版」与「真算版」分叉**的输入；否则改标签不构成证据。

**A 的含义（防止被读成「弱」）**
**A 不是弱，是「这份证据只到转录为止」。** 强度词表描述证据到哪儿，不描述结论对不对。
本轮 #8 由 R 降 A 的理由固定为一句：**它今天不出错，不是因为有人核过，是因为没人改动过。**

### 12.31 自毁式证明五段；豁免清单须逐项写理由（2026-10-25 冻结，对应 DISCIPLINES #19）

**纪律十七 · 失败输入测试若改动被锚定的产物，必须自带五段**
> **快照 → 改动 → 断言 → 复原 → 复验哈希**；复验失败即**整体失败**。

**原因是自我指涉**：证明「断言能失败」的手段，本身会破坏「结论有据可依」的前提。
我的原话（结构上今晚最重要的一句）：**我设计的失败输入测试，恰恰是唯一会破坏锚的测试。**
实例：R9 的分叉构造要改 `_m5db` 里的 `source_text`，而 `_m5db` 的内容哈希 `76df01317bfaf3e7` 是我们的锚。
⇒ 必须 ① 复制进 `_before/` 并登记 `copyist/copy_time/reason` ② 改动 ③ 断言分叉 ④ 复原 ⑤ **复验哈希回到原值**；④⑤ 失败即判不通过。

**豁免清单（`LEAD_ONLY`）须逐项写理由，且新增不得默认落入**
- **一条没有理由的豁免，与「排除掉失败的文件」同形**：看起来一样，实质不同。
- ⇒ 检查脚本对 `LEAD_ONLY` 每项要求**非空理由**，无理由即判失败（不是警告）。
- ⇒ 新增纪律**不得默认落入** `LEAD_ONLY`：负控「加 #N ⇒ `unhandled: [N]` 且 exit 1」已满足此条 ——
  它与负定义（`all − x`）的区别正在于：**未处理 ⇒ 失败，而不是「未处理 ⇒ 归入不适用」。**

**红得对的可读形式**：负控失败时必须打印 `unhandled` / `absent` 的**具体编号**，不只给 `exit 1`。
原因：崩溃与断言失败在 shell 里完全同形（`$? == 1`），**只有看输出才知道红的是什么**。

### 12.32 同形歧义、先读后写、文件名哈希须重算（2026-10-25 冻结，对应 DISCIPLINES #20/#21/#22）

**纪律十八 · 同形歧义：两个原因给出同一观测时，必须有第二个观测把它们分开**
实例：登记层出现「登记了但磁盘没有」与「磁盘有但没登记」两种不一致，
在计数上都表现为「数目不对」；必须分别报出**名字**，否则修错方向。
做法：检查器按「entry→disk」「disk→entry」「名字 sha 与内容 sha」三条**分别输出**，
每条都能单独失败。

**纪律十九 · 先读入内存，再打开写入**
实例：run_stage3_before.py 曾被整文件清空一次 —— 同一表达式里先 open(w) 再 open().read()，
前者把文件截断为 0 字节，后者读到的就是空串。能恢复的唯一原因是事先有 _before@dcf75778ac381629。
判据：仓库内禁止「同一表达式内先 open(...,'w') 再 open(...).read()」，且**必须给一条能命中的样例**，
否则它就是一条永远为真的断言。

**纪律二十 · 名字里带哈希的，必须从内容重算核对**
实例：_before/ 下 24 个带 @sha 的副本，今晚第一次把「名字声称的哈希」与「内容重算的哈希」比对 —— 全对，0 不一致。
⇒ 命名主张成立，**但成立的原因是今天才第一次核它**。
做法：登记层自检必须同时核三值：登记 source_sha16 / 名字里的 sha16 / 内容重算的 sha16。

**一条看起来繁琐的规矩，在它第一次救回东西之前，一直是纯成本。**
这就是为什么它必须在无动机时被建立（缺口先记，在无动机时登记）。
今晚 _before/ 第一次真正救回了一份工作 —— 它救回的是 run_stage3_before.py。

**A 档与 R 档在多段证明上的区别（R9 改进后的口径）**
R9 未在锚定产物上「改了再复原」，而是**在副本上做**：没有需要复原的东西，就没有忘记复原的可能。
⇒ 第 ④ 步「内容哈希仍等于 76df01317bfaf3e7」仍然执行，但它现在的含义是
**「锚确实没被写过」**（更强），而不是「复原成功」（较弱）。验收单必须写明是哪一种。

### 12.33 证据目录不得作运行时暂存区；isfile 而非 exists；可 import 的副本（2026-10-25 冻结）

**纪律二十一 · 证据目录不得作为运行时暂存区**
实测（我 05:4x 复核）：m4_verify_grounded.py:129-131 与 m5_fix_compare.py:32-34 **都在运行时**
把 git 里的 pre-R12 源码写到 _before/m5_ground_preR12.py，再用 spec_from_file_location 导入它。
⇒ 该文件是**生成物**，不是策展副本：此刻它**不存在**（跑一次才出现）。
⇒ 两条症状同因：① 它「名字不带 @sha」② 它的导入生成 _before/__pycache__。
**这比「名字不规范」重**：它把**证据面**与**运行时暂存**混在同一目录里，
于是「谁放进去的、代表哪一刻」不再可由目录语义回答。

**由此修正两条拟议裁定（否则会造出永远为真的判据 / 破坏生产）**
- 「_before 内所有 .py 一律改名 .py@sha16」：**会破坏** 两个 loader（它们写死文件名）。
  可行前提是**同一提交内**改这两个调用点；但更干净的是把 scratch 移出 _before（见下）。
- 「__pycache__ 再现即红」：当前实现**每次正常运行都会生成它**（因为那次 import 是设计的一部分），
  ⇒ 该判据会**恒红**。**一条永远无法满足的判据与永远为真的断言同病。**
  正确顺序：先把 scratch 移出证据目录，再让「_before 内出现 __pycache__」成为红。

**建议形态**
- scratch 落 tempfile.mkdtemp() 或 _scratch/（gitignored），**不落 _before**；
- _before 只保存**人登记**的副本，每个都带 @sha16 且在 REGISTER 里有 copyist/copy_time/reason；
- 之后 R11 的③才可写成：「_before 内允许的条目**正面枚举**（REGISTER.json 一条），其余出现即红」。

**纪律二十二 · 判「磁盘上有」必须用 isfile，并断言 basename 非空**
实例（A 项根因，由我查出）：某条登记的 copy_path 指向 m4 目录本身，basename 为空。
⇒ 路径**能解析**、os.path.exists **也为真**、但它**不是文件**。
「文件缺失」会被 ls 发现；**「路径解析成功但没有文件」不会**。
做法：assert os.path.isfile(copy_path) 且 assert os.path.basename(copy_path) != ""。

**证明性动作也要留复原证据（R9 重跑口径）**
在副本上重跑分叉输入后，**仍须复验** _m5db 内容哈希 = 76df01317bfaf3e7，
即使确定没碰它 —— 证明性动作与破坏性动作可能是同一步。

### 12.34 锚须满足「变了一定是错」；重跑登记格式；时刻须由程序打印（2026-10-25 冻结，对应 #24）

**纪律二十三 · 凡锚，必须满足「变了一定是错」；会被正常流程改写的量只能作观测值**
实例：_m5db **文件 sha** 今夜出现**五个**不同值（eb8838d8 / 9ee0bad9 / 08a485dc / 3f71fedb / 现测），
而**内容哈希始终 76df01317bfaf3e7**，块数 2、文本长度 [110,113] 不变。
⇒ 锚集合定为：**内容哈希 + 块集合**；文件 sha 与 mtime 只作观测值。
判据：一个会被别处正常重跑改写的数字，不能承担「不许变」——**它看起来是锚，其实是一次读数的快照。**

**重跑登记固定格式：who / when / why / scope / result**
> 例：`inspector / 05:36:54 / 独立重跑 R9 分叉输入 / 只写 tempfile 副本 / 内容哈希前后均等`
它要被**检索**，不是被阅读；且它是纪律二十要求的「第二个观测」——
「没被碰过」与「被验证过没被碰过」在纸面上同形，登记是唯一区分。

**时刻必须由程序打印，不得事后追记**
实例（我自己的错）：审计脚本 _r11.py **没有打印时钟**，我在报告里写成「05:40 审计」——
那是**追记的整数**，不是读数。事后用「当时 disk copies=25 + 文件创建时刻」只能**反推区间**（05:29:06–05:30:06），
反推是推理，不是测量，必须在验收单里标明是哪一种。
⇒ 凡时刻，printing time.strftime 的结果直接进产物；**没有打印过的时间一律写作「未测」**。

**一个断言只回答一个问题；「某时刻的事实」不是测试结果**
R8 拆两条：
- **R8a**「派生式能否返回 True」——输入可构造、可复现 ⇒ **档 R**。
- **R8b**「真实产物里所有行是否都为 False」——这是**关于某时刻的事实**，要变 R 需整跑 main()（会改写 PREREG 与两个库）⇒ **档 A**。
  **「不值得为它做」与「做不到」要分开写**：前者是成本判断，后者是能力边界，混写会让读者以为我们做不到。

### 12.36 纪律 26/27 落进判据（2026-10-25 补，作者=inspector；方向=收紧）

**#26 判据变更须标方向；看数据之后放松的界必须单列为「放松项」**
落法：M3 阶段所有界（`n_block=91`、`k=3`、`逐轮相等`）在 `M3-PREREG.md` 声明时**未见过任何一轮数据**；

理由是纪律 26 原话：**放松本身就是一条「我先看了数据」的自认**。

**#27 判据里的字面量须先证明存在于被判对象里；打印「在 / 不在」**
落法：`mine/inspector/check_needle_provenance.py`（常驻断言，可被驱动 import）：
```
assert_needle(block_text, NEEDLE, boundary=NEEDLE.replace(" ", ""), require="602")
needle='广陵路 12 号 2 单元 602' text_len=127 needle_in_text=在 | require='602' require_in_needle=在 | boundary='广陵路12号2单元602' boundary_in_text=不在
```

**我自己的两处缺陷（写进判据，不留在口头）**
1. 第一版**只验边界变体**，于是 `--needle "广陵路"` 是绿的 —— **「针太松」不是「边界变体在」的子集**：
   边界是**否定**命题（不该在什么里出现），核心内容是**肯定**命题（必须包含什么）。压成一条 ⇒ **只红在否定那侧，肯定那侧永远绿**。

2. `require` 是**作者的声明**，不是数据决定的常量 —— 它挪的是「针指向什么」，不动「判据严不严」，故安全；
   但**必须写进产物**，不能藏在脚本常量里（与「定阈值等于替数据选答案」互为镜像）。

**工具的射程（写在交付里，不等误用后解释）**
- 只证明「这根针在 / 不在」，**不证明「这根针是对的那根」**（后者只能靠人看上下文）；
- 不检查 `block_text` 本身是不是该编码的文本 —— **保证的是针与对象的关系，不是对象选对了**。

### 12.37 纪律 28/29 落进判据（2026-10-25 补，作者=inspector）

**#28 判据变更的第三类方向 = 改对象（放松 / 收紧之外）**
落法：M3 声明 §11 三条修订全部标注为**改对象**，并逐条给出「原声明 X → 改为 Y，因为 Z」。
判定标准（我自己后来总结的）：
```
改「严不严」 => 放松 / 收紧
改「测哪个对象」 => 改对象      <- 恒红判据属于这一类：它测的参照点在结构上不成立
```
**为什么必须单列这一类**：标成收紧会让读者以为强度没变（其实对象换了）；标成放松则像替自己开脱。
**而一条恒红的判据强度为零，改对参照点不等于降低要求，是把要求从「不可能」变成「可满足且可失败」。**

实例（三条都属于此类）：
1. `S3`：`pos_max_at_attach - pos_max_after_detach == 91` → 位置侧 `== pos_hi-1` + 格数侧 `attach-before == 91`。
   因为 `raw_pos_max` 是绝对位置，且 `kvshim_ask_at` 把问答写回同一序列，「detach 后」不是空序列（实测 4095-4146=-51）。
2. `C2`：`attach 格数 - detach 格数 == 91` → `attach 格数 - attach 前格数 == 91`（残差 51 = 本轮问答 token 数）。
3. `I1`：`rc != 0` 即无效 → 只看「空串 / needle 缺 / 位置失配」；`rc` 只记录。**实测每轮 rc=93 是常态**，按原字面 50 轮全废。
   这条没人指出，是我读逐轮原值时自己报的：**判据里一个没有来源的常量，就是作者的选择。**

**#29 退出码必须不经管道读取**
落法：凡断言 rc，一律 `cmd > file 2>&1; echo rc=$?`，禁止 `cmd | tail`。
实例：我用 `python … | tail -3` 读到 `rc=0`，以为是「FAIL 但退出码 0」；不带管道重测为 `rc=1`。
**因为 `tail` 的退出码取代了 python 的** —— 与「把一次读数当成锚」同族：**把观察方式的产物当成了对象的性质。**
**严重性**：它会让**所有**「我核过 rc」的陈述失效，包括此前的。**12.37 补写时刻**：06:03:27（方向=收紧：把两条纪律落成判据条文）
