## 1 判定一：`</think` 泄漏 —— 是产物缺陷，必须记录并处置

**我核了码点**：U+003C U+002F t h i n k U+003E，即 ``（闭合标签）。两条作答原文里各一段，位置在**答案的两个副本之间**：
- 住址：`我住在广陵路 12 号 2 单元 602。\n\n\n我住在广陵路 12 号 2 单元 602。`
- 车牌：`浙B-3F19K\n\n\n车牌号是浙B-3F19K。`

**判定：这是 M4 的产物缺陷（用户可见污染），不是"命中就算过"的小事。** 三条理由：
1. 它**确定性复现**：3 次独立生成（run_m4_write step5 一次、run_m4_verify 两次）全部出现，不是采样噪声；
2. 它**不是块正文带来的**：block_text 里我用子串查过，没有 think / 没有尖括号；块正文干净（这符合 block_text_policy 的逐字规定）；
3. 它**跨实验可对照**：M2 三个 run json + M3 的 50 轮答案里，`think` 出现次数**全为 0**；M4 两个 json 里是 **8 个字段承载**（write 2 + verify 6），但只是 **2 个不同答案串**（53 字 / 32 字；verify 里 `answer_exact` 与 `answer_checks/*` 逐字节等同于 `answers/*`）。**原写「6 次」作废**：那是保留 `answer_exact` 重复、剔掉 `answer_checks` 副本的不对称去重（纪律 38）。
   这说明它不是"这个模型天生会吐的标签"。

**但我不判它的成因**（证据不足，见下）。三个候选未排除：
(a) 块正文是**对话式**（含 assistant turn 的"你好！有什么可以帮你？""记住了。"）；

## 8 判定：answer / answer_display 规格够不够 —— 方向对，缺三条硬条件

**你的规格我认四条**：answer 逐字节原样 = 证据；answer_display = 剔除后展示；验收判据只用 answer；剔除规则写成常量并单测三情形。
**要补的（缺了就会变成「清洗器悄悄改句子」）**：

1. **差异可解释断言（最重要）**：diff(answer, answer_display) 必须能被「白名单标签 + 由此产生的连续空行合并」**完全解释**；
   出现任何其它差异（标点、空格、多删一个字、少删一个标签）⇒ **报错**，不许静默。这一条让清洗成为可机器验证的等比减法，而不是自由改写。
2. **幂等 + 无标签时逐字节相等**：f(f(x))==f(x)；无标签输入下 display 必须与 answer **逐字节相等**（写成断言，不是注释）。
   单测补两种情形：相邻连写（两个标签紧挨）、一批 ≥100 个。
3. **留痕四项进 json**：per_tag_count、removed_chars、display_len、display_empty；清洗后为空要置 display_empty=true 并记，**不许用原文顶替**。

**你问「是否要求 answer_display 也不含其它模板残留」——我判：要分类处置，不许一锅端。**
- **结构层**（控制标签）⇒ 必须剔，剔不干净就是失败；
- **内容层**（自问自答的问/答、同句重复 X\n\nX）⇒ **不许放进同一个清洗函数**，那会让证据链断裂；
  要处理就用独立开关 first_sentence_only（M2 起就一直按「交付只取首句」处理），同样只作用于 display、同样计数，
  并作为**告警**记录而不计入 pass/fail。理由：一旦清洗器开始删内容，就没人能证明 answer 与 display 的差额只来自标签了。
