# M4 判据 · 「什么值得记」（冻结，实现之前）

检测员 inspector ｜ 2026-10-25 ｜ 交付 mine/inspector/M4-CRITERIA.md
依据：docs/legacy-2026-10-24/STATUS-REPORT.md §4.4「分段（~500–1000 token）→ 判据（值得记的事实/承诺/偏好；忽略寒暄）→ write_at → save → 插 SQLite（编码必须独占 position 0）→ **验收：一次对话后自动沉淀 1 块，新进程能检索并正确回答。**」
MD 只给了"值得记的事实/承诺/偏好；忽略寒暄"一句原则。本文件把它变成**能对一段真实对话逐句给 keep/drop、且人能复验**的规则。
冻结后才允许实现；实现后只许在本文件 §12 追加修订。

## 0 边界与方向（先说清楚，免得又一轮辩论）

- **M4 判"该不该记"，不判"记得对不对"**。后者是 M5。M4 允许把一条用户原话原样存下；是否与块正文一致由 M5 管。
- **M4 与 M5 的取舍方向相反，这是故意的**：
  - M5：**漏判优先**（误把正确答成 unsupported 会毁掉产品）；
  - M4：**宁多记不漏记**（漏记住址/承诺/约束的伤害远大于多记一条偏好）。
  两条方向不能互换，也不许有人把它们"统一"成一种。
- **记忆的主体是用户**。assistant 的发言默认不记（见 D4 的唯一例外）。
- **一条记忆 = 一个三元组（主体, 属性, 值）+ 证据片段**，不是"一句话"。一段话可产多条，也可 0 条。

## 1 接口（写死，供实现与复验对齐）

输入：
- conversation：按轮的列表 [{"role": "user"|"assistant", "text": "...", "ts": "ISO-8601 或 null"}]；
- user_id：主体标识；
- 可选：existing_memories（用于去重）。

输出：逐句一条记录（**每一句都必须有输出，不许静默跳过**）：
  {sent_id, role, text, verdict: keep|drop|undecidable, code: K1..K6|D1..D7|U1..U5, reason: 一句话,
   memories: [ {subject, attr, value, type, evidence_span, anchored_time|null, confidence } ] }

"句"的定义：中文句界 。！？换行；一"轮"里可有多句。**问句与陈述句分开判**（见 D3）。

## 2 keep 六型（记）

| 码 | 类型 | 触发（机械可判） | 例 |
|---|---|---|---|
| K1 | 用户世界的**事实** | 含"我/我的/我家" + 判断词（是/叫/住/在/有/养/开/用/在…工作）且宾语是**可枚举的具体值** | 我住在广陵路 12 号 2 单元 602。／我车牌是浙B-3F19K。／我女儿小名叫豆豆。 |
| K2 | **偏好** | 喜欢/爱/讨厌/不吃/不喝/只喝/习惯/受不了/更喜欢/一般选 | 我的咖啡只喝美式，不加糖。／我不吃辣。 |
| K3 | **承诺与计划** | 我要/我会/打算/计划/约定/别忘了/下周三…（含时间或事件） | 下周三她生日，提醒我买蛋糕。 |
| K4 | **身份与关系** | 名字/小名/称呼/我是…（职业/身份）/我妻子/我老板 + 称谓 | 我女儿小名叫豆豆。／我在蓝鲸上班。 |
| K5 | **约束与规则** | 别/不要/以后都/请记住/不要再/总是… + 行为 | 我每天早上七点半出门，别在那个时候给我推消息。 |
| K6 | **显式要求记住** | 记住/记一下/存一下/别忘了（说话人明确要求持久化） | 记住我的车牌是浙B-3F19K。 |

一条句子可同时命中多型（如 K1+K3），**必须拆成多条记忆**，各带各自的 evidence_span。

## 3 drop 七型（不记）

| 码 | 类型 | 判据 |
|---|---|---|
| D1 | 寒暄客套 | 你好/在吗/谢谢/麻烦了/再见/晚安，且句中无其它陈述 |
| D2 | 过程性应答 | 嗯/好的/收到/稍等/我看看，无新信息 |
| D3 | **问句与请求本身** | 以 吗/呢/？/"多少/什么/哪/怎么" 结尾或开头的纯索取；**问句里的实体不记**（"我车牌号是多少？"不产生记忆） |
| D4 | assistant 发言 | 默认 drop。**唯一例外**：assistant 上一句给出一个具体事实，用户紧接着明确确认（"对/是的/没错/就是这样"）⇒ 记 1 条，标注 derived_from=assistant，confidence 降一档 |
| D5 | 时效性闲聊 | 天气/新闻/股价/"今天好热"，无持久面 |
| D6 | 一次性操作指令 | 打开/翻译/总结/查一下（不是偏好、不是承诺） |
| D7 | 纯情绪表达 | 我好累/烦死了，**除非带持续性**（"我长期失眠" ⇒ K1 健康） |

## 4 undecidable 五型（既不记也不丢，标给人工）

U1 **指代无法解析**（"它"、"那个东西"、"还是老地方"且上下文无锚）；
U2 **条件句/假设**（"如果我搬到杭州就…"）——不记成事实，除非用户说"已经搬了"；
U3 **相对时间无法锚定**（见 §7）；
U4 **否定范围不明**（"我不喜欢那个" —— 对象缺失）⇒ 记 U4，不许猜对象；
U5 **反讽/玩笑标记**（哈哈/开玩笑）且内容与事实矛盾。

**纪律：undecidable 不许被悄悄 drop。** 三个值必须都出现在输出里。

## 5 粒度、去重、合并

- 一条记忆 =（subject, attr, value）唯一。attr 用**固定小词表**（见 §6），不许自由生成新属性名，否则无法检索。
- 同一 (subject, attr) 出现多值：**保留最新并标 superseded**（旧值不删，标失效），不许静默覆盖。
  （住址搬了要能查历史；车牌换了要知道旧的不能用。）
- 同一三元组在同一对话里重复出现 ⇒ 合并为一条，evidence_span 取首次。
- 一条句子产生 ≥2 条记忆时，全部输出，不许只留第一条。

## 6 属性词表（冻结，可追加不可悄悄删）

住址 出生地 生日 年龄 姓名 小名 称呼 职业 单位 家庭成员 宠物 车牌 车型 电话 邮箱 账号 设备
饮食偏好 饮品偏好 忌口 作息 通勤 常去地点 健康 过敏 长期约束 提醒规则 计划 承诺 目标 语言偏好

（不在表内的新属性 ⇒ 记 **undecidable(U-attr)** 并写进待审清单，不许直接落库。理由：自由属性名会让"新进程能检索"这条验收无法达成。）

## 7 相对时间必须锚定

- 出现 明天/后天/下周X/下个月/月底/今晚/三天后 等 ⇒ 必须用对话的 ts 转成**绝对日期**，存 anchored_time。
- 对话**没有 ts** ⇒ 该条记 **undecidable(U3)**，不许把"下周三"原样存下来（一周后它就错了，这是最隐蔽的脏数据）。
- 有 ts 但用户说的是"每年/每个周三" ⇒ 存 recurrence，不转单点日期。
- **周界定义（冻结）**：以 ts 所在周的周一起算一周；"下周X" = 下一个周一之后的第 X 天。
  例：ts=2026-10-25（周日）说"下周三" ⇒ 下周从 2026-10-26（周一）起 ⇒ **2026-10-28**。
  民间另有一种读法（把 11-04 叫"下周三"），**判据只认 10-28**，实现不许自选；若实现给 11-04，判实现错。

## 8 与分段（容器）的关系

- 分段是**容器**（500–1000 token，MD §4.4），keep 是**内容**；两者解耦：
  - 一段里 0 条 keep ⇒ **该段不落块**（纯寒暄对话不产生记忆，这是"忽略寒暄"的落地方式）；
  - 一段里 ≥1 条 keep ⇒ 该段落块，块的正文 = 该段的**原文**（不改写），记忆行写 SQLite 并指向该块。
- 落块时正文必须是原文逐字（M5 校验依赖它），**记忆三元组是索引，不是正文的替代**。

## 9 写入前的接地

- 每条 keep 的 value 必须在 evidence_span 里**逐字出现**（数字/日期/专名尤其），否则该条降为 undecidable。
- 这是 M4 与 M5 的共同底盘：M4 保证"存的是原话"，M5 保证"答案不超出块正文"。
- 编码写入时**必须独占 position 0**（MD L6），且要有一条总线断言：同一 seq 上 position 0 只能属于一个块。

## 10 取舍（写死）

- **宁多记不漏记**：K1/K3/K4/K5 的 recall 要求 **1.0**（漏一条住址/承诺/约束/身份都是产品事故）；
  precision 目标 ≥0.8（多记一条偏好可接受）。
- K2（偏好）允许漏，但漏了不许当"无偏好"处理 —— 输出里必须区分"没有偏好"与"没记到"。
- **D7 与 K1 的边界**：情绪表达一律 drop，除非出现"长期/一直/总是/每次"⇒ 按 K1 健康或 K5 约束记。这条今晚容易被误判，写在这里。

## 11 样例对话 + 逐句预期（先写死，实现后逐句对照）

对话（ts = 2026-10-25T09:00:00，全部为 user 除注明）：

| # | 句子 | 我的预期 | 产出记忆 |
|---|---|---|---|
| 1 | 你好呀！ | **drop / D1** | — |
| 2 | （assistant）你好！有什么可以帮你？ | **drop / D4** | — |
| 3 | 我住在广陵路 12 号 2 单元 602。 | **keep / K1** | (用户, 住址, 广陵路 12 号 2 单元 602) |
| 4 | 我每天早上七点半出门，别在那个时候给我推消息。 | **keep / K1+K5（两条）** | (用户, 作息, 每天 07:30 出门)；(用户, 提醒规则, 07:30 前后不推送) |
| 5 | 我车牌是浙B-3F19K。 | **keep / K1** | (用户, 车牌, 浙B-3F19K) |
| 6 | （assistant）记住了。 | **drop / D4** | — |
| 7 | 帮我查下明天天气。 | **drop / D3+D6** | —（既非偏好也非承诺；"明天"也不锚定） |
| 8 | 谢谢，就这样吧。 | **drop / D1** | — |
| 9 | 对了，我女儿小名叫豆豆，下周三她生日，提醒我买蛋糕。 | **keep / K4+K3（两条）** | (用户, 家庭成员, 女儿小名豆豆)；(用户, 计划, 2026-10-28 女儿生日买蛋糕, anchored_time=2026-10-28) |

注意：第 9 句的"下周三"必须按 ts 锚成 **2026-10-28**（10-25 是周日；按 §7 周界定义，下周从 10-26 周一起，
下周三就是 10-28）。若实现给出的是"下周三"原串、或 11-04、或别的日期，**判实现错**。

附加四条边界预期（同样写死）：
- 「我不吃辣。」⇒ keep / K2（忌口=辣）。
- 「我不喜欢那个。」⇒ **undecidable / U4**（对象缺失），不许 drop、不许猜。
- 「我好累。」⇒ drop / D7；「我长期失眠。」⇒ keep / K1（健康=长期失眠）。
- 「如果我搬到杭州，你会记得吗？」⇒ **undecidable / U2**（条件句，不是事实），不许记成"住杭州"。

## 12 验收清单（实现方要交）

1. 上一节样例对话的**逐句**输出（每句都要有 verdict + code + reason；缺一句即不完整）。
2. 九句的期望对照：一致 / 不一致逐条列出；不一致**不许改判据**，先报。
3. 时间锚定：第 9 句 anchored_time 的实际值，是否为 **2026-10-28**（按 §7 周界定义；11-04 也算错）。
4. 去重：把第 3 句在同一对话里重复一遍，确认不新增记忆行、只更新 evidence。
5. 多值覆盖：先记"住广陵路"，后记"搬到文昌路" ⇒ 必须两条都在，旧值标 superseded（不许静默覆盖）。
6. 落块与独占：本次对话产生的块数、每块 position 0 独占断言的结果、SQLite 行数与 keep 条数一致。
7. **新进程检索**（MD §4.4 的验收原文）：另起一个进程，问"我住在哪？"「我车牌号是多少？」，要求答出且与存的值逐字一致。
8. 一行结论：MD 的验收「一次对话后自动沉淀 1 块、新进程能检索并正确回答」是否达成（达成/未达成 + 阻塞项）。

## 13 已知边界（防过度宣称）

- M4 判的是**该不该记**，不判记进去的内容是否被模型正确使用（那是 M2 取块 + M5 接地）。
- 属性词表是封闭的：新属性的处理方式是"报 undecidable"，不是"自动扩建词表"；扩表要走判据修订。
- 对 assistant 发言的例外（D4）只覆盖"用户明确确认"一种情形，**不覆盖**"assistant 从用户话里总结出的事实"——
  那种必须回到用户原句取证据，否则会形成"模型自证"的污染链（今晚 14B 的 F 跑就是活例子）。

## 14 判据修订记录

### 14.1 数据之后追加的修订（2026-10-25，M4 已落地并实测后）

**R6 · 检索单元与 KV 块分离（数据之后补，结构性）**
- **块**是上下文单位：1 块 = 1 段原文，正文逐字（M5 接地依赖这一点，不许改写/摘要）。
- **检索单元**是块正文的**逐字子串**：1 单元 = 1 条证据句。两者通过 source_block 映射绑定。
- 硬约束：① 单元文本必须是块正文的子串（可断言）；② 每个单元必须映射到**实际挂载**的块；③ 每个单元至少对应 1 条记忆行；
  ④ **不得为通过检索门限而修改 GATE / COV_MIN 常量**（阈值保持冻结值），必须记录被拒与被接受两侧的实测分；
  ⑤ 同一文本只建 1 个单元，并记录 fanout（该单元对应几条记忆）。
- 补因：整段 91 token 对话当单元被 M1 门拒（score 0.575 < 1.30、coverage 0.12 < 0.35），同一事实单独当单元则 3.203 通过。

**R7 · 指代型相对时间的处置（数据之后补，裁决 §7 与 §9 的冲突）**
- "那个时候 / 那天 / 那时候 / 那时" 这类**指代**不是可锚定的相对时间，但把它解析成绝对时间又会破坏 §9 的"value 必须逐字出现"。
- 裁决：value **保持逐字原文**，同时在 DB 增加 resolved 字段（resolved_value 或 resolved_time），把解析结果写进去；
  **不许只存原文而无解析字段**（否则检索不到、人也看不懂），也不许把解析结果替换进 value。
- 补因：实测"别在那个时候给我推消息"被 keep 且无任何解析字段，指代悬空。

**R8 · 句口径必须声明（数据之后补）**
- §11 的表是按**轮**列的；实现按**句**（句界 。！？）输出：本样本 9 轮 = 10 句（assistant 那轮切成两句，均 D4）。
- 两种口径**不许混用**；报告必须写明本次口径与句数；keep 条数在两种口径下必须一致（本样本 6 条）。

**R9 · 同一证据句的多条记忆共享一个检索单元（数据之后补充说明）**
- 允许一条证据句产出多条记忆（如 K1+K5），但检索单元必须**按文本去重**，并记录 fanout；
  不许对同一文本建两个检索单元（否则同一句被索引两次、双命中污染排序）。

### 14.2 数据之后追加的修订（2026-10-25，think 标签归因收窄后）

**R10 · 证据与展示分离（answer / answer_display）**
- run json 的 answer **逐字节原样**保存 = 证据；新增 answer_display = 剔除控制标签后的展示文本。
- **所有验收判据只用 answer**；answer_display **不参与任何 pass/fail**。
- 清洗是纯函数、确定、**幂等**（f(f(x)) == f(x)）。
- 白名单常量（冻结，追加需走修订）：</think> </response> <|im_start|> <|im_end|> </s> <s>。命中才删，**不做其它任何改写**。
- **差异可解释断言（本条是硬条件）**：diff(answer, answer_display) 必须能被"白名单标签 + 由此产生的连续空行合并"完全解释；
  出现任何其它差异（标点、空格、词序、多删一个字、少删一个标签）⇒ **报错**，不许静默。
- 留痕：per_tag_count、removed_chars、display_len、display_empty 四项必须进 json。
- 空结果保护：清洗后为空 ⇒ display 为空并置 display_empty=true 并记；不许用原文顶替、不许编造。
- 单测四情形：句首 / 句中 / 多处（含相邻连写与 ≥100 个）/ **无标签时 display 与 answer 逐字节相等**。
- **分层纪律（防清洗器变成改写器）**：控制标签属**结构层**，必须剔；"问：/答："自问自答与同句重复属**内容层**，
  不许塞进同一个清洗函数（否则证据链断裂）。要处理同句重复，用独立开关 first_sentence_only，同样只作用于 display、同样计数。

**R11 · think 标签的触发条件（归因，收窄但未锁死）**
- 观测（我复核 evidence_think_tag.json）：A 完整对话 91 tok → has_tag=True；B 散文单行 55 tok → False；C 去 assistant 轮 82 tok → **True**。
  另：M2 两跑 + M3 50 轮答案里标签 0 次；M4 verify 里 4 次。
- 可下结论的：**与 assistant 轮无关**（C 仍触发），与问句模板无关（模板字面不含标签）。
- **还不能下结论的**：A/C 是**换行拼接的多行正文**，B 是**单行散文**，同时长度不同（91/82 vs 55）、续写模式不同（rc 93 vs 230）。
  "换行/多行结构"与"内容/长度"两个变量**未分离**，所以只能说「多行块正文相关」，不能说"对话记录形态"就是原因。
- 待做的单例实验（零风险、一次引擎）：把 A 的同样文本里所有换行换成空（内容一字不改），若不再出标签 ⇒ 换行/多行是必要条件。
- **影响**：M4 的产品形态就是"对话记录段落落块" ⇒ 这是**主路径必现**，不是边缘情形 ⇒ R10 的展示层清洗是必需品。
- **禁止**为此改块正文（加引导头/摘要）——违反 §8 逐字策略，并切断 M2/M3/M4 的可比性。
