# 无证据策略（NO-EVIDENCE-POLICY）

> 2026-11-06 · 判定层规范，不改产品默认、不改 K5；配套 `tools/no_evidence_policy.py`。

## 1 原则

1. **追问必须是模型澄清**：系统只提供检索结果/“无证据”信号，不得把“手机号”映射成“微信号”等未确认属性；不得用系统规则编造答案。
2. **可以返回手机号，但必须说明这是手机号**：允许“你只告诉过我手机号 X，没告诉我微信号；这是手机号”；**禁止**把手机号说成微信号（“你的微信号是 <手机号>”）。
3. **词法边界（KNOWN）**：当前**无别名表、无句向量检索**；检索是 **BM25/词法匹配**，因此“微信 vs 手机号”不会因语义相近被自动等同。

## 2 可判定规则（validator）

`no_evidence_policy.check(question, answer, memories)`：

- question 含“微信” 且 answer 含 11 位手机号（允许 `-`/空格分隔）时，**三条同时成立才 pass**：
  1. answer 含有限定语（`这是手机号` / `不是微信号` / `微信没说过` / `没告诉我微信号` / `只告诉过我手机号` 至少一）；
  2. **不得**出现“你的微信号是 X / 微信号是 / 微信号为”，也**不得**让手机号直接挂在“微信号”后（如“微信号：138…”）；
  3. 记忆里**确实存在手机号**（否则必须拒答，不能拿别槽顶）。
- 只给值、无说明 → `phone_unexplained_for_wechat` fail；无手机号证据 → `phone_without_memory_evidence` fail；冒充 → `phone_claimed_as_wechat` fail；三条齐 → `phone_explained_not_wechat` pass。
- 其余情况 `ok=true`（非微信问题、答案无手机号等）。

## 3 回归样例

| 问句 | 答案 | 记忆 | 判定 |
|---|---|---|---|
| 我的微信号是多少？ | …138-0000-2222 | 只有手机号 | **fail**（未说明） |
| 我的微信号是多少？ | 你只告诉过我手机号 138-0000-2222，没告诉我微信号 | 只有手机号 | pass |
| 我的微信号是多少？ | 这是手机号：138-0000-2222 | **无手机号** | **fail** |
| 我的微信号是多少？ | 138-0000-2222 | 只有手机号 | **fail**（无说明） |
| 我的微信号是多少？ | 你的微信号是 138-0000-2222 | 只有手机号 | **fail**（冒充） |
| 我的手机号是多少？ | 138-0000-2222 | 手机号 | pass |
| 我的微信号是多少？ | 没有记录 | 只有手机号 | pass（拒答/澄清） |
| 我的微信号是多少？ | wx_abc | 有微信事实 | pass |

## 4 范围与限制

- 这是**判定器/回归门**，不参与线上回答生成；K5 槽位直答仅覆盖 phone/fitness，问“微信”不会触发。
- 不建别名字典、不加向量；若未来引入语义检索，必须先更新本文档与规则。
- 不做自动改写、不写库。
