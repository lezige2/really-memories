# 工业级人机协同记忆架构 · A 评估（提交 B）

> 用户提案：三层（规则高置信自动 / 不确定追问 / LoRA 只做预填）+ 四梁八柱 + 40k 压测 + 大厂自主性训练借鉴（StreamVibe/Self-Direction/Environment Scaling/GRPO）。

## 1 三层策略：方向对齐，但有一个产品缺口

- 自动/追问/顾问三层与我们已定的 hybrid 一致；规则 v2 precision 1.0、LoRA safe gain −2 是证据。
- **缺口**：产品目前没有“追问 UI”。QQ 桥/CLI 能否弹一次选择（更新旧值 / 新增）？没有交互面，“追问”落不了地。
- 建议最小实现：写入返回 `needs_confirmation` + 两个选项；CLI/QQ 桥显示，用户点选后提交；不猜、不自动覆盖。

## 2 40k 压测：用户假设与当前代码有两点不一致（必须先纠正）

1. **容量溢出不是 LRU 淘汰**：`_insert_memory_block` 在 `len(rows) >= LIBRARY_MAX(200)` 时直接 `raise DailyError("memory_full")`，**不会剔除最老废话**。所以“塞到 200 看淘汰是否精准”当前会得到“写入被拒”，不是“淘汰最老”。
2. **norm_hash 去重尚未实现**：现有 `_put_memory_source` 只用 `source_hash`（原文精确哈希）判重；全角/空白差异的 5 对脏数据**不会被 norm_hash 拦住**（norm_hash 只在 ENGINEERING-CLEANUP-SPEC 里规划）。
3. 因此压测要么按**当前真实行为**写（200 拒绝、仅精确重复拦截），要么先实现 norm_hash + 淘汰策略（产品变更，需 B 审、会改写入语义）。

## 3 自主性训练：SFT+负样本今晚做，RL 不在本窗口

- 大厂用 GRPO/环境/奖励模型；我们目前只有 600 条合成数据 + simulator 40 条，**没有环境、没有 reward model、没有轨迹**，上 RL 是空转。
- 可借鉴的是**评测口径**：三向（漏触发/误触发/内容错）、严重度、三次运行稳定性；不照搬训练算法。
- 今晚仍按 SFT+负样本；若数据门过即训；RL 留作后续（需环境与 reward 设计）。
