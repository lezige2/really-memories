# K3′ 预注册：属性组内重排（只重排，不隐藏）

## 目的
验证“挂载顺序”是否影响旧值串味；这是 PREREG 中从未跑过的一项，不是换属性重复。

## 触发
- 仅 phone（手机号/手机/电话 + 我）与 fitness（健身 + 几点/什么时候/时间）；
- 有值块 ≥2、无多实体线索；
- 其他问题不触发（触发率必须 ≤30%）。

## 操作
- 同属性有值块按 created_at/id **最新在前**重排；
- **不隐藏**任何块；无值块放后，原顺序稳定；
- 响应/日志记 `attribute_rerank{attribute, order, reason}`，order 是实际挂载顺序。

## 预注册门（缺一不过）
1. MT20 5× paired：on 不低于 off；
2. 无 case 从 4–5/5 掉到 0–2/5；
3. 触发率 ≤30%，且只 phone/fitness；
4. 逐 case 记录实际挂载顺序，证明顺序确实变化（否则实验无效）；
5. 统计答案含旧值比例；若 on 没降，结论为“顺序无效”。

## 失败处理（现在写死）
- 不过 → **封存质量线**；
- 交接写“读侧排序无效，质量瓶颈在模型自身”；
- 不再开新属性、不再换信号、不再做第 N 次尝试。
- 默认保持 off；v1 功能交付不受影响。

## 边界
- 只测顺序，不测删块/embedding/rerank 模型；
- 构造对抗集不能替代真实 MT20；
- 结果不外推线上分布。
