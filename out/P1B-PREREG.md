# P1b 预注册：主体键与写时冲突（软覆盖/追问）

> 2026-10-30 · 仅预注册，**不写码/不 commit/不重启** · flag 默认 off
> 配套 spec：`out/P1B-SUBJECT-CONFLICT-SPEC.md`

## 1 假设

1. 多数“同槽换值”是**同主体**更新（cue/时间锚点可判），应软覆盖；
2. 主体判不出时（两车/两号未指定）追问比覆盖安全；
3. 复用现有 confirm token 即可，不需要第二套确认机制；
4. sidecar 可重建、可删除，不构成第二真相源。

## 2 数据（全部新造，不复用 Q40/S2 旧题）

- **held-out A：多主体链 12 条**（`P1B-H01..H12`）：每链 3–4 块，含
  * 单主体更新（cue+时间锚点）→ 期望软覆盖；
  * 两辆车/两个号/两个人的同谓词并行链 → 期望互不影响；
  * 链中夹旧值陷阱（文本说“现在”但时间戳更早）→ 期望按时间/主体判，不按措辞；
  * 主体缺失句（“我的车是白色”）+ 族内两车 → 期望 ambiguous/追问。
- **held-out B：上一轮 5 条“内容无据”样本（仅作答案层回归，不当写侧标签）**：这 5 条是 verifier 答案层样本（`unsupported`），**不得**用作 P1b 写侧的“应覆盖/应追问”标签；只用于验证“P1b 软覆盖不得改变这些答案”（答案文本/判定不变）。
- 另造 6 条**否定/冲突**样本（不是/已经不在/旧值中石油）→ 期望追问或弃权，不得软覆盖。
- 全部由**非实现者**（C2/R2）独立标注，产物 `out/P1B-HELDOUT.jsonl`；**冻结后给 sha256**（C2 记录），实现者不得改标签；held-out 不参与实现期调参。

## 3 协议

1. flag off：与现网逐字比对（抽 20 条 `/remember` 请求，响应键/值一致）；
2. flag on：只跑 held-out A/B + 否定样本；`/remember` 触发/确认走现有 token 接口；
3. 服务级回归：81 / extra / MT20（clone 库 + 隔离端口）；
4. 每次触发/覆盖记 `reason`、`candidates`、`subject`、`supersedes`、sidecar sha。

## 4 通过门（全部满足）

| 维度 | 门 |
|---|---|
| 安全·误覆盖 | **0**（错主体/错值/否定被覆盖均为 0） |
| 同秒/并发 | `created_at` 相同取 id 大者；`(tenant,subject,predicate)` 串行化、串行区内 last-writer；`same_second_conflict` / `serial_conflict` 逐条审计，**双覆盖=0** |
| K2 同开 | 20 块库、K2 auto on + P1b on：同链只挂最新、两车互不隐、主体缺失不双隐；`block_ids` 与单开 P1b 基线一致，**双覆盖/双隐=0** |
| cue/锚点 | cue 只认 SPEC §2.1 清单；锚点只用 `created_at`(v1_local_naive)，`event_date` 禁止依赖 |
| 主体一致性 | `换成/换到` 在 车/车牌/手机号/银行卡 族必须叠加主体一致性；主体判不出→追问（字面 cue 单独命中=FAIL） |
| 更正 cue | 记错了/搞错了/其实是/之前说错 本轮不启用，按“无 cue→追问”；不得边跑边加 |
| 安全·追问/弃权 | 否定/冲突/ambiguous 样本 **100%** 追问或弃权，不得静默写 |
| 覆盖·单主体 | 单主体链（清单 cue + created_at 锚点）软覆盖正确 **12/12** |
| 覆盖·互不影响 | 多主体并行链互不覆盖 **≥10/10**（两车/两号/两人） |
| 漏覆盖 | 无 cue 且无锚点 → 追问/弃权 **100%**；漏覆盖仅允许出现在“无法判定”，且需逐条解释 |
| 确认复用 | token 单次/TTL≤5min/绑定 tenant+文本 sha+session；confirm 后仅一次 `_put_memory_source`；回答层 5 条答案不变 |
| 产品回归 | 81=81/81、extra≥19、MT20≥18；flag off 逐字不变；P50 ≤ +20% |
| 副作用 | 不 ALTER daily；删 sidecar 后行为回现网 |

- 任一门失败 → P1b FAIL，flag 保持 off，sidecar 删除；不进入实现迭代，除非重新预注册。
- 版本标签：所有新数字标 `p1b`；旧数字标 `v2/v2.1` 或各自基线，不混算。

## 5 判定规则

- 安全 > 覆盖：宁可追问/弃权，不得误覆盖；
- cue 只认清单、锚点只用 created_at（v1_local_naive），禁止依赖 event_date；
- 同秒冲突取 id 大者并计数；同键串行化、串行内 last-writer，禁止双覆盖；
- 不确定即 `ambiguous`，禁止“取最大 id / 取最新”式猜测；
- 同链整链处理，跨链不共享覆盖；
- **反问率上限 20%**（追问次数/写入次数）：>20% 判“追问过多”，先查触发条件（cue 清单/主体判定），
  **不得**为降追问率放宽安全门；到线不放宽。

## 6 回滚

- 若 sidecar 丢失：产品行为自动回到现网（可重建，不影响块/原文/id）。
