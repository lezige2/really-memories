## 附录：B 反驳书（原文）

**核心裁决：**

1) **S1 全部否决其"先改再验"路径**。S1 的失效面就是 h411 本身（HANDOFF §96/§103 已定性为 heldout 无 per-case reset 的上条 case 会议室串场）。20 块常驻+只 attach/detach 2 块，等于放弃 seq 起点、prompt cache、detach 是否真清 KV 的保证；而 `--reset-per-case/--forget-created-per-case/--hermetic` 是本轮报数口径的一部分，改它即换臂，禁止与冻结的 79/81、88–91/92 配对。"逐字等价"必须定义为：每条 completion 的 token id 序列 sha256 全等 + 挂载集合/顺序/detach 序列/seq 起始 pos/memories 计数全等；不等即判"实现错误"（复用 ROUND1 §6），不得记为阴性。且 42×5 的等价验证本身要跑满，S1 省不了这一次时间。

2) **S2 只许判阴、不许判阳**。n=42、base~25% 时 McNemar 不一致对 b+c 天然很小，§3 已定 b+c<10 为"证据不足"；SPRT 的 H0 边界在该区几乎不可能被真正接受，实际只会在 max 5 停而报告被读成"阴性"。5 次还是同一 case 的重复测量，违反 SPRT 的 iid 前提。并新增一条禁令：不得对已采 BASE r1–r5 事后套用停止规则（data-dependent stopping，最严重的一类 p-hacking）。

3) **S3 本轮不做**。收益 10–25%、验证最贵、与答案正确性耦合最强。42 条是冲突集短答，81/92 才是长答（k03 352 字、多段 clean_answer）；截断落在免责句或代码围栏时判据仍 pass → 假 pass。42 条一致不能外推 193 条；要 81+92+20 零触顶才敢用，成本反超收益。

4) **S4 未过冒烟前不得排期**。块是 persistent-memory 私格式，绑定 build 8e5a58d+本地 llama.h 改动、模型 sha、q8_0、n_ctx/chat_start 布局；审计 §9 连 A10 登录都不成立（key 被拒），Linux kvshim 未验证。重建块非同一批 bytes → 跨机数字无法与本地 BASE 配对。两实例共用 chat.db 会与 `--forget-created-per-case` 写库冲突，须各持独立库副本；2×14B+32768 KV 在 24GB 上近顶。且 mount 占 30–50% 说明瓶颈在引擎调用/IO，并行未必线性。

**认可的最小测量计划（按序、前一步不通过不进下一步）：**
①只读打点：原命令加计时，3 条×1 次，量 mount(20)/detach/ask/reset 的 wall time 与引擎调用数；指标=mount 占比、p50/p95。mount<20% → 弃 S1。
②≥20% 则 5 条×2 臂×1 次，只作串场/可行性筛查，判据同 C1，出现泄漏或不等即停。
③等价性正式验证 42 条×2 次（等价是确定性断言，不需 5 次）；过了才进 42×5。
④S2 仅离线模拟：用现有 r1–r5 逐条结果算停止分布与"被读作阴性"比例，只评估方法、不改判据。
⑤S3/S4 本轮不测。

**测完之前不许改**：n_predict、三个隔离开关、topk/ngl/n_ctx/chat_start/模型路径、20 块库、判据与 pass 阈值、`start_service*.cmd`、预登记 sha256。

**必改条款**：C1 等价口径=token 序列 sha256+挂载断言全等、样本 10→42；C2 顺序停止只判阴、禁事后套用、b+c<10 一律"不可判定"；C3 S3 验证域改 193 条零触顶，否则不做；C4 S4 未过 A10 冒烟不排期、块只重建不搬运。

**Veto**：V1 用无 per-case reset 跑法比 BASE 报提升或更新基线；V2 把 b+c<10 写阴性；V3 以 42 条一致外推改评测态 n_predict；V4 未冒烟宣称 2 路可行；V5 以速度为名改判据/阈值/pass 口径。

**净判断**：S1/S2 可作为方法论加速但都必须挂在确定性等价断言上；S3 放弃；S4 属跨环境变更，在 K2/K3′ 未开工前不插入。总提速实得预计远小于 A 的 40–60%，先拿打点数字再谈。
