# JUDGE-ROBUSTNESS-SPEC —— 抽取式判据的失效模式与兜底规范

> `frozen=true` · `rev=1` · `frozen_at=2026-10-26T17:15:00+08:00` · 冻结人：LEAD
> 定位：**`tools/m5_judge.py` 与 `tools/chat.py` 接入前的强制前置规范**。本件不实现代码，只规定行为。
> 触发来源：用户"终极拷问"（格式崩溃 / 同义替换 / 解析失败兜底）+ rev4 臂2 实测翻车（2/6）

## 0 铁律（先于一切细节）

1. **结论不得依赖"模型会守规矩"**。模型输出是**不可信输入**，与外部 HTTP 响应同级对待。
2. **每个失败都必须落到一个已定义状态**，不允许"崩掉/异常退出/静默跳过"。
3. **产品兜底遵循 M5 边界 2：漏判优先于误判**——宁放过一条编造，不冤枉一句真话。因此 `parse_fail` 默认**放行**，但**必须留痕 + 触发降级**。
4. **验收口径与产品口径分离**：产品放行的 `parse_fail`，在验收统计里**计入漏判**并**单列 parse_fail 率**。
5. **双实现交叉校验**：解析器由 executor 与 inspector **各自独立实现**，同一输出两份解析不一致 ⇒ `parse_fail`。

## 1 失败模式总表（每条必须有归宿）

| # | 失败模式 | 实例 | 归宿状态 | 是否降级 |
|---:|---|---|---|---|
| 1 | 完全不按格式 | 输出散文/英文/空 | `parse_fail` | 是（>5% ⇒ 未接上） |
| 2 | 格式部分破坏 | 只有 `条目：` 没 `依据：` | 有界修复 1 次 → 仍败 ⇒ `parse_fail` | 是 |
| 3 | 标签词变体 | `项目：` `证据：` `- ` 列表 | 词表归一 ⇒ 正常解析 | 否 |
| 4 | 缺席词变体 | `没有提到` / `N/A` / `—` | 缺席词表（22 变体） | 否 |
| 5 | **否定式证据** | `不是 GZ-5517，而是 GZ-9911` | **否定规则 ⇒ `absent`** | 否 |
| 6 | **值不一致** | 条目 `下周二` / 依据 `下周四` | **值校验 ⇒ `absent`** | 否 |
| 7 | **编造依据** | 引用源文里不存在的片段 | 引文校验 ⇒ `absent` | 否 |
| 8 | 同义/近义改写 | `俱乐部` vs `健身房` | 模糊匹配 ≥0.80 ⇒ present（记 `fuzzy`） | 是（>30% 告警） |

| 12 | 超时/引擎异常 | 调用失败 | `unverifiable` → 产品放行 | 是 |

## 2 第 0 层：确定性前置（不调用模型）

```
if source.strip() == "":                      verdict = unsupported  (route=empty_source)
elif ABSTAIN_RE.search(sentence):             走弃答核查 (route=abstain_check)
else:                                         进第 1 层
```

- **弃答正则（含窄选项，rev4 实测修正）**：`(没有|未|无从|不曾)\s*(提|提过|提及|提到|记录|说明|写明|给出)`；
  与 `(不知道|不确定|无法提供|没有相关信息)`
- **弃答核查**：抽取被声称缺失的对象词（去套话、按标点切分、过滤停用词），逐个在 `source` 子串查找：
  - 全部不在源文 ⇒ `abstain_ok`（**不计编造、不计支持**）
  - 任一在源文 ⇒ `abstain_wrong`（按 `unsupported` 处理：它否认了记忆里存在的信息）
- 对象词为空 ⇒ `undecidable`（弃答句没给出可核查对象）

## 3 第 1 层：模型只抽取（唯一一次前向，不给选项、不要结论）

prompt 逐字见 `PREREG-M5-C2-REV4.md be618108a82c2f42` §1 第 1 层。**禁止**：选项、字母、要求判定、GBNF。
生成：`temperature=0`、`n_predict=384`、独立前向。

**有界修复**：解析失败时，最多再做 **1 次**修复前向（原输出 + "请只按 `条目：/依据：` 重新输出"）；
仍失败 ⇒ `parse_fail`。**修复次数硬编码为 1，不允许循环**。

## 4 第 2 层：确定性裁决（不调用模型）

对每个 item 依次应用 **R1→R4**，任一命中即 `absent=true`：

| 规则 | 判定逻辑 | 抓什么 |
|---|---|---|
| **R1 值校验** | 条目中提取"具体值 token"（数字+单位、日期 `下周X/8月X日`、型号 `[A-Z]{2,}-\d+`、机构名 `X公司/X店/X院`）；该 token 须在依据片段中出现（精确，或字符二元组覆盖率 ≥0.80） | **值不一致**（下周二 vs 下周四） |
| **R2 否定校验** | 依据片段中，条目内容出现位置**前 6 字符内**有否定词（`不/没/非/无/并非/不是/而不是/另一/改为/换成`），或匹配 `不是{条目}` / `并非{条目}` | **否定式证据**（不是 GZ-5517，而是 GZ-9911） |
| **R3 缺席词表** | 依据归一化后命中缺席词表（`未提及\|没有提到\|未找到\|找不到\|未记录\|无对应\|无相关\|未涉及\|未写明\|未说明\|未给出\|未提供\|N/A\|NA\|None\|null\|—` 等） | 模型明说没有 |
| **R4 引文校验** | 依据中带引号/片段的原文，在 `source` 中**逐字不存在** ⇒ `absent` | **模型编造依据** |

**整句裁决**

| 条件 | verdict |
|---|---|
| `len(items)==0` | `undecidable` |
| 任一 `absent==true` | `unsupported` |
| 全部 `absent==false` 且 ≥1 条 | `supported` |
| 条目/依据无法归类（既非缺席词、也无可匹配引文） | 该条 `unverified` ⇒ `undecidable` |

**推理型断言（第 4 层旁路）**：句子含 `共/总共/合计/一共/平均/最/加起来/合计` ⇒ `derived=true` ⇒ **强制 `undecidable`**，
**禁止判 `unsupported`**（否则会冤枉合法推理）。

## 5 产品侧（chat.py）行为与降级

| verdict | chat.py 行为 |
|---|---|
| `supported` | 正常返回 |
| `unsupported` | 返回 + **标注「此句记忆中没有依据」**；可配置为拦截 |
| `undecidable` / `parse_fail` / `unverifiable` | 正常返回 + 计数（**不拦截**，遵守边界 2） |
| `abstain_ok` | 正常返回 |
| `abstain_wrong` | 按 `unsupported` 处理 |
| `empty_source` | 正常返回 + 标注「当前没有可用记忆」 |

**开关**：`M5_JUDGE_MODE = off | shadow | enforce`，**默认 `off`**。
- `shadow`：跑判据但不改输出，只记日志（**首次上线必须用这个**）
- `enforce`：`unsupported` 才真正拦截

**降级（自动，必须留痕）**
- 滚动 100 次内 `parse_fail 率 > 5%` ⇒ **装置 `未接上`**，自动降为 `off`，并在界面明示"校验不可用"
- `fuzzy` 比例 > 30% ⇒ 告警（不降级）
- 单次判据耗时 > 3 s ⇒ 告警（不降级）

## 6 强制自测（接 chat.py 之前必须全绿）

`tools/m5_judge.py` 自带 `--selftest`，**≥24 例**，其中**至少 8 例是恶意/畸形输入注入**：

| 类别 | 例数 | 要求 |
|---|---:|---|
| 正常抽取（支持/编造/缺席/否定/值不一致） | 8 | 判定正确 |
| 畸形输出（空/纯英文/乱码/截断/无标签/标签混排/只有依据没有条目/超长重复） | 8 | **一律 `parse_fail`，不得抛异常、不得误判 supported** |
| 边界（空源文/弃答/推理型/引文编造） | 8 | 按 §2/§3/§4 状态 |

**判定**：`selftest_all_pass=true` **且** `no_exception_raised=true` 才允许接入 chat.py。

## 7 与 chat.py 的耦合边界

1. `tools/m5_judge.py`：**纯函数**，输入 `(source_text, question, sentence)` → `verdict` 字典；不读全局状态、不写文件、不打印。
2. `tools/chat.py`：仅新增一次 `judge()` 调用 + 一个开关；**生成路径、记忆路径、KV 路径一律不动**。
3. `verify.sh`：新增 12 条断言（含畸形输出不崩、`parse_fail` 放行留痕、`derived` 不判编造、开关 off 时零影响）。
4. **接入顺序**：`m5_judge.py` 自测绿 → `shadow` 跑 1 次产品回归 → 再评估 `enforce`。
