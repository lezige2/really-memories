## §0 判法（先定死，再读代码）

### 0.1 什么算「一处冲突」——四要件缺一不可

1. **同一判定对象**：同一个 query × 同一候选块集合（同一输入）。
2. **两处口径**：两个可以各自独立给出裁决的地方（判定处/判定层）。
3. **裁决相反**：两处对同一输入给出**不同的准入结果**（答 vs 拒、放行 vs 杀掉），
   或同一判据表在**同一属性**上被两个反例夹住（过宽 + 过窄）。
4. **可复现**：我能构造出触发输入的实测（不是读注释猜的）。

### 0.2 不算冲突的

- 只有措辞/行号/注释差异（`M4-ACCEPT` 的 G8 就是我在这条上翻过的车，见 `INSPECTOR-M4-ACCEPT.md` §8 C1）；
- 同一处里的两条阈值，若**从未产生不同裁决** ⇒ 记「待定」，不记「真」；
- 记录更正/补记/表述更正（按 §13.3 共同条，方向只有 `放松/收紧/改对象` 三值；非判据变更另行标注）。

### 0.3 三态

`真冲突`（有构造性反例，必须处置）/ `假冲突`（记录即可，不立项）/ `待定`（要实例，还没造出来）。
**假冲突与待定都不得写成"冲突"充数。**

### 0.4 计数规则（回应派单「不许凑三」）

一处 = 一个**可构造反例的裁决对**。不合并两处为一项（会漏修），不把一处拆成两项（会凑数）。
**实际几处报几处**；legacy 写"三条机制冲突"，我按实测报 **4 处**（3 条 legacy + 1 条新发现），理由逐条见 §1。

### §1.1 M18-1 属性闸门 vs 词法闸门（legacy §8.2 第 1 条）

**legacy 原文（README L269-270）**：
> `1. **属性闸门与词法闸门打架**：属性已把候选收窄到正确块，`COV_MIN/REL_CUT` 又把它拒了`
> `（问"电话"，块里写"手机号" -> 二元组不重叠 -> 空）。属性一旦确定块，词法覆盖率不该再当裁判。`

**① 侧（放行）**：`retrieval.py:241-250`
```

if want_prop:
    scope = A.scope_of(query, want_prop)
    allowed = {sid for sid, txt in con.execute("SELECT id, text FROM memory_source")
               if A.property_holds(txt, want_prop, scope)}
    if not allowed:
        return []
```
配套 `analysis.py:189-211 property_holds`（要求 value 与属性词/作用域锚点相距 ≤5 字）。

**② 侧（杀掉）**：`retrieval.py:323` / `:328` / `:338-340`
```
if s > 0:                      # L323   —— 没有分就根本进不了候选
...
if not out or not _passes(out[0]):   # L328
...
keep = [r for r in out if r["score"] >= max(top * REL_CUT, ABS_CUT)]   # L339
```

**复现（构造库，块 = `我的手机号是 13800138000。我在供应链分析组工作。`）**：

| 探针 | 读数 |
|---|---|
| `A.property_of('我的电话是多少')` | `phone` |
| `A.property_holds('我的手机号是 13800138000。','phone')` | `True` ⇒ `allowed={1}` |
| `R.search('我的电话是多少')` | **`[]`（ABSTAIN）** |
| 对照 `R.search('我的手机号是多少')` | `profile score=3.789 cov=0.48` |

**真实库读数（`kvmem/chat.db` `237d8e1f5de9a382`，10 块已建索引）**：

| query | ① 的 `allowed` | ② 的结果 |
|---|---|---|
| `我的地址是什么` | `[1,2,3,5]`（**5 = `conv_2026-10-25#L3`，正文 `我住在广陵路 12 号 2 单元 602。`**） | **ABSTAIN** |
| `我的住址是什么` | `[1,2,3,5]` | **ABSTAIN** |

⇒ 属性闸门把正确答案 5 放行，二元组（我住/住址/地址）在块里一个都不重叠，于是全灭。
**判：真冲突**（拒答方向；legacy 已裁"属性一旦确定块，词法覆盖率不该再当裁判"）。
**注意**：在今天的代码里，杀掉它的具体闸是 **L323 的 `s > 0`**（进不了候选），不是 legacy 提到的 `COV_MIN/REL_CUT`
——`REL_CUT/ABS_CUT` 的那一半被 M18-4 单独证到。

### §1.2 M18-2 值模式过宽/过窄（legacy §8.2 第 2 条）

**legacy 原文（README L271-272）**：

**① 侧原文**：`analysis.py:128-152 PROPERTIES`，关键两行

以及 `analysis.py:189-211 property_holds` 的兜底：

**②③ 侧没有补偿规则**（这点很重要：三处冲突不是靠 ②③ 打补丁维持的，是 ① 一张表自己两向出错）。

**复现（构造库 + 真实库，两向各给读数）**：

| 例 | 方向 | 构造读数 | 真实库读数 |
|---|---|---|---|
| birthday 无作用域 | 过宽 | `property_holds('合同 12月15日到期。','birthday') = True`；query `我生日是哪天` 在"只有该块带日期"的构造库里 **返回 contract `score=2.661`**（误答） | `attr` 表：source 2（`蓝鲸项目定在 3月14日 上线`）被判 **`birthday`** |

（`(3,address)`、`(5,address)`：正文里确实有住址，判对是碰巧）。

**判：真冲突，两向并存**。同一条目内两向是 legacy 的记法，我**不拆成两处**（拆开会凑数），也**不合并掉任何一例**（5 个实例都指向同一根因：无作用域的通用模式 + 无锚默认放行）。

### §1.4 M18-4（新发现，不属于 legacy 三条）词法闸门内部自相矛盾

**位置（同一模块两闸）**：
```
L343-345  def _passes(best):
              """Absolute evidence, or explanatory coverage."""
              return best["score"] >= GATE or best["signals"].get("cov", 0.0) >= COV_MIN
L338-340  top = out[0]["score"]
              keep = [r for r in out if r["score"] >= max(top * REL_CUT, ABS_CUT)]
              return keep[:k]
```
**同一输入两闸相反**：`_passes` 判"过"（覆盖率路径），紧接的 `keep` 又用 **绝对下限 `ABS_CUT=1.10`** 把唯一候选删光
⇒ `_passes` 的"explanatory coverage"分支在实现上**不可达**，除非分数也 ≥1.10。

**复现（构造库：1 个长块 135 terms / 10 块 / avg 21.6，块内含一次 `金`，query `我的公积金账户余额多少`）**：

```
n_docs 10  avg 21.6  weak True  rare ['u:金']  allowed {1}
cov {1: 1.0}   score {1: 0.633}
_passes(top) = True        keep survives = False        ABS_CUT = 1.1
R.search(...) = []         R.search(..., explain=True) = []   # explain 空 = 走到 keep 才被删
```
（`explain=True` 返回空列表而不是 `(none)` 记录，正因为 `out` 非空、`_passes` 已过、死在 `keep`。）

**判：真冲突（② 内部）**。不并入 M18-1：M18-1 是"① 已放行仍被杀"，本处与属性无关，纯词法态即可触发。
**严重度**：本处单独看是**假红**（该答不答）；但与 M18-1 联动时会把"先修 M18-1、阈值不动"的方案反咬一口（see §2.3 顺序）。
