## 1 v2.2 判据（先验写死；实现时不得改）

**1.1 句级支持判据**（替换 v2.1 的 `facts[].sentence` 聚合）
- `supported` ⟺ 句中**每个可核成分**都被 facts 覆盖；否则 `unsupported`（≥1 成分未覆盖）；
- 句中无可核成分 ⇒ `no_fact`；成分不可判定（截断残句 / 繁体豁免 / P-c 豁免）⇒ `undecidable`（不进两率分母，单列）。

**1.2 归一化（先做，后抽成分）**
```
NFKC → strip → 去空白 → 去标点 [，。！？、；：,\.!\?;:""''（）()【】\[\]「」『』]
中文数字串转阿拉伯：零〇一二三四五六七八九十百千万亿两（十位/百位按标准进位，两→2）
```

**1.3 可核成分抽取（纯规则、无模型；四类 + 确定形式）**
① 数词串（中文/阿拉伯；带边界，防列表序号与小数混入）：
```
NUM = re.compile(r"(?<![.．、])(?:[0-9０-９]+|[零〇一二三四五六七八九十百千万亿两]+)(?![.．、])")
```
② 实体词（**必须命中下列 6 个模式之一**，否则不产生实体成分）：
```
SUFFIX_ENTITY = re.compile(r"[\u4e00-\u9fff0-9]{1,10}(?:路|街|道|巷|弄|号|楼|单元|室|层|栋|座|区|市|省|县|镇|村|园|苑|府|湾|广场|大厦)")
TIME_ENTITY   = re.compile(r"(?:\d{1,2}月\d{1,2}[日号])|(?:\d{4}[-/年]\d{1,2}[-/月]\d{1,2})|(?:\d{1,2}[:：]\d{2})")
CODE_ENTITY   = re.compile(r"(?:代号|名称|型号)(?:为|是|：|:)?\s*([A-Za-z0-9\u4e00-\u9fff]{2,12})")
PLATE_ENTITY  = re.compile(r"[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼][A-HJ-NP-Z][A-HJ-NP-Z0-9]{4,6}")
LOC_ENTITY    = re.compile(r"(?:在|到|去|回)([\u4e00-\u9fff]{2,8})")
OBJ_ENTITY    = re.compile(r"(?:停在|停放在|停放|手持|拿着|带着)([\u4e00-\u9fff0-9]{2,10})")
```
③ 关系谓词（固定词表；最长优先、重叠取最长）：
```
PREDICATES = ("住在","住址","地址","停在","停放在","停放","上线","发布","代号","只喝","喝","加糖","不加糖","不加奶","是","为","在")
```
④ 否定词（字符级；与其后谓词/实体绑定为一个成分，如「不加糖」）：
```
NEG = ("不","没","没有","非","未","无")
```
抽取顺序：② 实体（最长优先）→ ③ 谓词 → ④ 否定绑定 → ① 数词；每成分记 `(text_norm, kind, span)`，`kind∈{num,entity,predicate,neg}`。

**1.4 覆盖判定（写死；v2.1 `len-2` 的收紧版、方向反转）**
- 成分 `c` **被覆盖** ⟺ ∃ fact `f`：`c` 是 `f` 的子串（归一化后）**或**（`f` 是 `c` 的子串 且 `len(f) ≥ len(c)-1`）；否则**未覆盖** ⇒ 该句 `unsupported`。
- 对照：v2.1 复用 v1 的 `len(key)-2` 匹配（`m5_ground.py:255`），语义是「答案级有 fact 命中即支持」；v2.2 改为「**每个成分各自必须被覆盖**」，任一未覆盖即整句 unsupported。
- **预声明宽松点**：`f⊂c 且 len-1` 允许单字差（`2单元` vs `单元`）；该分支可能把「在杭州」在存在「杭州」fact 时放行 ⇒ 验收单列 `short_fact_cover[]` 计数，只披露、不调规则。

**1.5 保留 v2.1 的**：θ=0.20 固档、2-gram 分支（**仅**答案级 `facts==[]`）、STOP/FRAME 常量断言、问句排除、`known_fp_controls` T6–T10/C6–C10 单列不进两率。
**1.6 新增单列**：`partial_hit_sentences[]`（给 `covered[]`/`uncovered[]`）、`extraction_fp[]`（列表序号/短语误抽/截断数字）、`branch5_structural_gap[]`（答案级 unsupported 无法落句时显式记账，不丢弃）。
**1.7 禁**：accuracy/F1/总分；用剔除后数字替代原始全量（原始与剔除后并列）；在 (c) 上调 θ/改词表。

## 3 已知风险与伪改善（预登记先声明）

- **收紧必然抬高误判**：「广陵路 12 号 2 单元 602 在杭州」前段全对、仍判 `unsupported`（LOC 成分「杭州」未覆盖）——这是**设计目标**不是缺陷；「只喝美式咖啡」vs 源「只喝美式」这类**修饰差异**也可能被判 unsupported。**误判率预期上升**；验收不得只看漏判率，必须双率 + `partial_hit_sentences` + `extraction_fp` 全量并列。
- **抽取器是最大风险（本件关键工程）**：三类假阳性必须**结构性排除**，不得事后剔除：
  1. **句首列表序号 `\d+[.、]`**：抽取前先剥句首 `^(?:\d{1,3}[.、)]|[（(]\d{1,3}[）)])\s*`；`NUM` 再带 `(?<![.．、])…(?![.．、])` 边界 ⇒ 「1.」永不入成分；剥离动作记 `extraction_fp[kind=list_ordinal_removed]`（计数应=被剥离句数，不是"漏抽"）。
  2. **句末截断数字（12→1）**：先标 `truncated_tail`（答案末句无终止标点，或触 `n_predict` 上限）；若末成分 `kind=num` 且 `span[1]==len(text)` ⇒ **不入成分**，记 `extraction_fp[kind=truncation_cut]`；若剥离后残留可影响覆盖判定 ⇒ 整句 `undecidable`（对应 R5 口径），不猜。
  3. **短语型误抽（「修正后的回答」）**：采用**正向上下文要求**——实体成分只由 §1.3 的 6 个模式产生；该短语不匹配任一模（无后缀/非时间/非车牌/非 LOC/非 OBJ/非代号值）⇒ **结构上不可能成为成分**；另加 `PHRASE_BLOCKLIST = frozenset({"修正后的回答","回答","以上","以下","现在","所有","等等","错误","正确"})`，只用于 `CODE_ENTITY` 捕获值与引号值位的二次排除。
- **不得声称解决**：驱动级问题、GPU 活跃期 crash-safe、θ 已校准性。
