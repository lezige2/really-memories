# ANSWER-VERIFY —— 答案核对机制（T9 文档 · 草稿）

> **状态：设计已定；实现依赖 T1–T4 接口，当前代码尚未落地 ⇒ 本文为*起草*，相关功能标「待实现 / 待实测」。**
> 行为口径（v1.4 目标）：**答案先核对，再返回**；不通过会**重答一次**；仍不通过则给固定兜底句。

## 1 机制图

```
用户提问
  │
  ├─ 无记忆命中/寒暄/能力/联网检索 ──► 各自确定性路径（不进核对）
  │
  └─ 基于已挂载记忆块生成答案
        │
        ▼
   [核对] 答案是否被记忆证据支持？
        │
   ┌────┴─────────────┐
   │通过               │不通过
   ▼                  ▼
返回答案         [修复/重答]（仅 1 次）
（verify_repair=false）   │
                    ┌────┴─────────┐
                    │通过            │仍不通过
                    ▼              ▼
              返回重答答案     返回兜底句
              （verify_repair=true） （verify_fallback=true）
```

## 2 触发条件（草案，以 T1–T4 接口定稿为准）

- 发生在**生成答案之后、返回用户之前**（CLI 与 HTTP 服务同一路径）。
- **只看"有记忆依据"的答案**：个人事实类答案进入核对；无记忆命中的个人事实问题走**固定拒答**，不进核对。
- **不进核对**：寒暄/能力内省（确定性回复）、只读联网检索答案（带来源）、无记忆的通用知识回答（待 T1–T4 确认）。

## 3 修复仅 1 次

- 核对不通过 ⇒ 带"核对失败原因"**重新生成 1 次**（repair）；**不无限重试**（避免延迟线性叠加）。
- 重答仍不通过 ⇒ 不再生成，直接返回兜底句；**同一问题最多 1 次修复**。

## 4 失败兜底句（固定文案）

> **「这条我没法从记忆里核对，先不猜。」**

- 固定文案、不调模型、不再重试；日志记 `verify_fallback=true`。

## 5 日志字段（落 `kvmem/assistant/sessions/*.jsonl` 的 answer 事件）

| 字段 | 类型 | 含义 |
|---|---|---|
| `verify_repair` | bool | 是否发生**过**1 次修复重答（true=重答后返回） |
| `verify_fallback` | bool | 是否落到**兜底句**（true=未通过且重答仍不过） |

> 其它核对明细字段（原因/命中证据/核对耗时）待 T1–T4 接口定稿后补；日志隐私模式仍按 `redacted/full/hash_only`。

## 6 开关

- 环境变量 **`LLAMA_MEM_VERIFY`**：控制是否启用核对（关闭=退回 v1.3 行为）。
- **取值与默认值待 T1–T4 接口稳定后确认（未核实）**；文档落地时在此写死并与 `tools/chat_daily.py` 常量对齐。

## 7 已知限制与延迟

- **不是"真伪证明"**：核对只回答"答案能否被已挂载记忆证据支持"，不保证世界知识正确；不覆盖联网检索答案。
- **延迟增加**：核对 + 最坏 1 次重答 ⇒ 最坏路径明显慢于单次回答；P50/P95 待实测（本页落地后补）。
- **误判风险**：短答案/指代不清/记忆证据跨句时可能核对失败（错误兜底）或误通过，待实测调优。
- **可关闭**：`LLAMA_MEM_VERIFY` 关闭后完全回到 v1.3 行为（不改记忆/不改模型）。
