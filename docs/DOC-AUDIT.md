## 2 文档为什么会错（根因归纳）

1. **"写结论的人"与"跑出结论的人"分离**：文档作者抄旧结论，没有回代码/产物复算；
2. **"目标值"被写成"已验证值"**：如 8.0 GiB 目标、6 条记忆、6,000 字对话窗；
3. **"登记"被当成"控制"**：冻结只写时间戳，没有只读/复核门槛；
4. **"状态词"吞掉"分量"**：四态词被大而化之，掩盖可测的越线分量；
5. **"实现选择"被写成"制度"**：读法主/敏、层数 36 等；
6. **旧文档只增不删**：PROGRESS 长到 319 KB，正确信息被历史噪声淹没。

## 3 以后的正确写法（规则，已生效）

1. **代码 → 文档**：任何数值/路径/命令先 `file:line` 或实件 sha 验证；写不出来就标 `未核实`；
2. **三层引用**：结论 → 冻结件 sha16 → 产物路径；不引聊天、不引记忆；
3. **状态词 + 分量并列**：四态之外，可测分量（如 FP 可测而 leak 不可测）必须单独写；
4. **双记**：`sha256 + bytes + mtime + declared frozen_at`，四者并列；
5. **只读 + 唯一一次解冻**：冻结就设只读；解冻必须留 changelog/旧 sha/授权件；
6. **一页入口**：根 `README.md` 只留入口与状态；历史长文进 `docs/archive/`；`docs/_work` 保留冻结证据，不进阅读主线；
7. **禁语**：不得写「接近达标」「就差一点」「样本量不足导致」「再多一点数据就能过」；
8. **临时件隔离**：`out/` 只放终件；`.tmp`/中间件进 `tmp/` 或 `_aborted_*/`。
9. **拒答/寒暄的行为规则**（应用层，不靠模型）：**寒暄/能力类走确定性回复**（`_smalltalk_reply()`，不调模型）；**无记忆的个人具体事实默认固定拒答**（`refused=true`，不调模型）；**对话内追问仍可答**（`dialogue_evidence` 只认 bigram/实体，不认单字 `u:`）。回归：`tools/test_refusal_cpu.py`（13 checks）。
